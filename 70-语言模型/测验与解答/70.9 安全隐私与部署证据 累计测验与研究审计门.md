# 70.9 安全隐私与部署证据 累计测验与研究审计门

> [!abstract] 通过定义
> 本门不以“看完八节”或“能背安全术语”为通过。学习者必须在一个从未见过的合成 Tool-RAG 案例上，独立完成资产/威胁、隐私测量、权限控制、拒答代价、版本复现、线上监控、事故记录与证据卡，并能明确哪些结论只是 benchmark 证据、哪些需要认证或线上证据。

## 一、前置题库

- LM65—72 各 15 题，A—E 五层，每层 3 题；
- 共 120 个唯一题号，解答文件使用完全相同题号一一对应；
- 闭卷抽取每节点至少 1 道 B 手算、1 道 C 推导、1 道 D 反例、1 道 E 迁移；
- 任何涉及真实秘密、攻击载荷、凭据或未授权目标的作答直接停止，改用合成占位符和防御性抽象。

## 二、八项累计任务

### G1　隐私对象与 Exposure

给定合成 canary manifest，手算 rank/exposure，分开 inclusion、memorization、reproduction、extractability 与 harm；写攻击接口、prefix 知识、查询预算、匹配与核验。

### G2　成员推断与删除

在固定低 FPR 下估计 TPR/PPV 区间；画出 $H_0/H_1$ 与 reference distribution；为删除请求追踪 raw→dedup→token→checkpoint→adapter→index/cache→served versions，并区分重训、认证和经验验证。

### G3　Tool-RAG 威胁模型

写资产、目标、知识、通道、预算、成功条件六元组；画 trust boundary；模型只提交 typed proposal，模型外 reference monitor 至少检查 identity、schema、scope、policy、confirmation。

### G4　红队与拒答

构造 attack family × language × tool permission × severity 矩阵；同时报告 harmful 漏放、benign 误拒、safe-completion、群体 coverage 和 adaptive budget，不允许用“全拒绝”取胜。

### G5　版本与复现

生成 model/tokenizer/template/prompt/decoder/RAG/tools/judge/environment manifest 与内容指纹；给出 R0—R3 复现目标、golden serialization tests 和不可固定 API 的时间窗 probe。

### G6　线上监控

写三个含窗口、slice、eligible 分母、失败规则、区间、owner 和 runbook 的 SLO；区分输入 drift、concept/measurement/system shift；解释被回答样本反馈为何不是目标总体。

### G7　Incident

从 first bad event 到 detect、mitigate、recover 写时间线；区分 trigger、proximate mechanism、contributing condition 与 control gap；每个行动项含 owner、期限和可执行验收。

### G8　证据卡

写一条对象/比较/总体/阈值/不确定性/版本齐全的 claim；生成 Model、Data、System 三卡和 PROV 图；保存 supporting、contradicting、unknown、expiry 与 invalidation triggers。

## 三、硬失败项

出现任一项即不得以总分补偿：

1. 真实敏感数据或未授权系统进入实验；
2. 没有 threat model/预算却声称安全；
3. 把无抽取、AUC=.5 或某攻击失效写成隐私保证；
4. 模型自己决定高权限动作且无外部授权；
5. 只报 harmful refusal，不报 benign utility/over-refusal；
6. 只写模型名，不保存 tokenizer/template/API/tool 版本；
7. parser/timeout/拒答被静默从分母删除；
8. incident 无回滚、证据或 owner；
9. Card 链接失效、只有聚合分或覆盖旧版本；
10. 标准/厂商文件被写成独立复现或安全认证。

## 四、评分量规

| 维度 | 25 分表现 |
|---|---|
| 理论与手算 | Exposure、PPV/低 FPR、删除距离、risk–coverage、TV/PSI 与 CI 口径正确，量词和分母清楚 |
| 威胁与系统 | 资产/权限/数据流完整，reference monitor 与 least privilege 可执行，攻击内容保持防御性抽象 |
| 实验与复现 | 对象/版本/独立单位/预算/失败齐全，raw artifacts 可重算，固定与 adaptive test 分离 |
| 线上与证据 | SLO/alert/rollback/incident/Card/PROV 闭环，支持/反对/未知与失效条件均记录 |

总分至少 85/100，且四维均至少 20/25、硬失败项为零。静态资料通过不等于个人掌握；学习者必须交独立工件并口头答辩。

## 五、研究审计口试

答辩者必须在不看答案时解释：

1. 为什么 exposure 高不等于泄露？
2. 为什么 AUC 不能替代 TPR@低 FPR？
3. 为什么数据库删行不等于模型遗忘？
4. 为什么 system prompt 不是权限系统？
5. 为什么 toxicity 不等于 harm？
6. 为什么安全与正确置信要双 score？
7. 为什么模型名相同仍可能不是同一对象？
8. 为什么漂移检测不等于质量检测？
9. 为什么时间线不等于根因？
10. 为什么 Card 完整不等于结论真实？

每题必须给定义、反例和更强证据，不接受只背结论。

## 六、最小交付包

交付目录至少含 protocol、threat-model、bundle manifest、synthetic data manifest、per-unit traces、metrics/CI、red-team matrix、authorization decisions、SLO dashboard snapshot、incident drill、Model/Data/System Cards、PROV graph、results 与 reproduce 命令。原始敏感内容不得进入包；受限工件只存加密引用和访问说明。

# 第七章语言模型累计测验与研究审计门

> [!abstract] 通过定义
> 学习者必须把一条语言模型结果从原始 bytes 追溯到 tokenizer、概率目标、训练数据、适配参数、上下文/检索、解码服务、评估估计量与部署风险，并能指出每个结论的量词、证据等级、替代解释和失效版本。文件存在、会调用 API 或复述架构名均不计为通过。

## 一、考核结构

本章已有 LM01—72 共 1080 题/1080 份逐题解答。个人考核分三层：

1. **闭卷基础卷**：从每卷 120 题中随机抽 10 题，共 90 题；每卷至少含 A 定义、B 手算、C 推导、D 反例、E 迁移各 1 题；
2. **跨卷口试**：从九条因果链中随机抽 3 条，现场画对象图、给反例并提出更强实验；
3. **综合研究工件**：完成一个全链路语言系统审计包；可用玩具模型/合成数据，但所有公式、分母、版本、失败和复现命令真实可执行。

闭卷 30%、口试 25%、研究工件 45%。总分至少 85/100，且九卷均不得低于本卷满分的 70%；硬失败项不能由总分补偿。

## 二、九卷累计能力

### 1. 文本与 Tokenization

给定一段含组合字符、emoji、未知字节和特殊 token 的输入：

- 区分 byte/code point/grapheme/token/document/window；
- 手算 NFC/NFKC 差异、BPE rank、WordPiece greedy、Unigram Viterbi/marginal；
- 证明 decode(encode(x)) 的适用域并构造反例；
- 报 bytes/token、fertility、UNK/fallback、群体切片与资源成本；
- 保存 normalization、pre-tokenizer、vocab、model、special-token/template 的完整版本。

### 2. 概率目标

从联合分布推出 causal chain rule，写 CLM/MLM/span corruption/prefix objective 的可见关系、target set 和归约分母；能解释：

$$
\operatorname{PPL}=\exp\!\left(
\frac{-\sum_i\log p(t_i\mid h_i)}
{\sum_i 1}
\right)
$$

为何只在 tokenizer、token unit 和 target law 固定时可比。必须能构造“伪似然条件相容但未定义同一 joint”“sample share 不等于 target-token share”的反例。

### 3. 预训练数据

从 raw archive 建立 parse/filter/dedup/contamination/mix/packing/token shard/checkpoint 的 provenance：

- 手算 Jaccard、MinHash/LSH candidate probability、mixture sampling 与 packing mask；
- 区分精确/近似去重、benchmark overlap、成员隐私与时间截止；
- 保存 rejection reason、许可/主体、有效 token 与 split 隔离；
- 不把 filter 后 benchmark 上升写成无偏或合法性证明。

### 4. 指令适配与 PEFT

把 messages 编译为 token IDs，手工标出 causal shift、response-only mask 与 global denominator；计算 full fine-tune、LoRA/QLoRA/Adapter/Prefix/IA3 的参数和显存账；证明 LoRA merge 等价的条件，解释 task vector/soup/TIES 何时因基座、置换或局部几何失效。

### 5. ICL 与推理时计算

把 prompt 当条件事件而非“模型能力本体”：

- 设计 order × label mapping × demo content × formatting 的析因实验；
- 区分 Bayesian/linear regression/GD 解释的 toy 假设与真实模型机制；
- 用 activation patching/ablation 讨论 induction circuit 的因果证据；
- 分开 CoT 正确性与 faithfulness；
- 手算 pass-at-k、self-consistency、search tree、verifier selection 与预算；
- 对长上下文报告证据位置和 effective length，而非 advertised length。

### 6. RAG 与工具

从

$$
p(y\mid x,\mathcal C)
=\sum_zp_\eta(z\mid x,\mathcal C)p_\theta(y\mid x,z)
$$

推导 top-$K$ 近似与 responsibility；手算 BM25、RRF、ANN recall、对比梯度、MRR/DCG。必须把 corpus answerable、retrieved、context available、generated correct、citation supported 分成独立事件，并保存 source snapshot、ACL、chunk/index lineage 和 multi-hop state。

### 7. 解码与服务

由 logits 手算 stable softmax、temperature、top-$k$/top-$p$/typical/min-$p$，说明截断后重新归一化；区分 greedy/beam/search score 与任务质量；写 EOS/stop/unlikelihood/grammar state；计算 KV cache、continuous batching、TTFT/TBT/goodput；推导 speculative decoding 接受校正并保存 draft/target/rollback trace。

### 8. 评估与事实证据

先写 target population、estimand、sampling/cluster unit、失败分母与版本，再选指标。能手算 EM/F1/BLEU/ROUGE、pass-at-k、Brier/ECE/risk–coverage；分开 truth、task/reference、grounding、citation correctness、attribution completeness；审计 LLM judge 的 AB/BA、长度、tie 与人类锚点；把 contamination/prompt sensitivity 写成诊断证据而非单因果证明。

### 9. 隐私、安全与部署

分开 memorization/exposure/extraction/harm，按低 FPR 审计 membership，用 retrain distribution 定义删除参照；为 Tool-RAG 写 threat model、trust boundary 和模型外 least-privilege reference monitor；同时报告 harmful 漏放与 benign over-refusal；固定 model/API/tokenizer/template/tool/judge bundle；建立 SLI/SLO、drift、feedback、rollback、incident 与 Model/Data/System Cards。

## 三、跨卷因果链口试

候选题包括：

1. Tokenizer 更新怎样同时改变训练 token 预算、PPL、上下文长度、KV cache、拒答和 benchmark 可比性？
2. Dedup 怎样影响有效 token、记忆、contamination、Scaling Law、pass-at-k 与隐私攻击？
3. Chat template 怎样贯穿 SFT mask、ICL、RAG context、解码 stop、judge 与 API 复现？
4. 一个 RAG 答案正确为何仍可能 attribution 失败、隐私失败或工具安全失败？
5. 多样本解码为何能提高 oracle coverage，却可能因 verifier、judge 和成本选择而降低部署效用？
6. 模型拒答率变化来自能力、校准、policy、template、traffic drift 还是攻击分布？怎样识别？
7. API 同名更新后，哪些历史实验可复算、重放、重实现或只能外部复验？
8. 线上反馈为何会改变下一轮训练数据，并造成 performative/selection loop？
9. 如何把一次 incident 反向连接到 data、model、prompt、tool、metric 与 owner？

每题必须给至少一个 DAG/流程图、一个数学对象、一个反例和一项可证伪实验。

## 四、综合研究工件：从请求到证据卡

选择一个无高危能力的合成任务，例如带公开小语料的离线问答。交付：

1. raw bytes/document 和 Unicode/tokenizer manifest；
2. 目标关系、loss positions 与 denominator；
3. data card、filter/dedup/mix/packing/provenance；
4. base/adaptation bundle 与参数/显存账；
5. prompt/demo/retrieval/decoder factorial；
6. per-request retrieval、generation、citation、tool/latency trace；
7. estimand、paired/cluster interval、failure denominator 与 hard gates；
8. 合成 canary、prompt-injection trust boundary 与拒答 paired set；
9. bundle hashes、reproduce 命令、SLO、rollback drill；
10. Model/Data/System Cards、claim ledger 与 PROV graph。

必须保留失败运行和与主张相反的证据。研究工件的核心不是模型规模，而是对象和证据闭合。

## 五、研究主张量规

每条主张标记为：

- I：由定义直接得到的恒等式；
- T：明确假设下的定理；
- A：为计算或解释引入的近似；
- E：限定模型/数据/预算/版本的经验结果；
- H：可证伪的机制假说；
- O：尚未解决或证据不足的问题。

博客可承担中文解释、问题入口和 H；论文中的 E 仍受实验设置限制；官方文档承担当前接口事实；标准承担术语/过程，不自动产生性能与安全证明。

## 六、硬失败项

1. 训练/测试泄漏、用 test 选择 prompt/checkpoint/threshold 后仍称确认性；
2. 只写模型名，不写 tokenizer/template/sampler/retriever/judge/tool/API 版本；
3. 省略 timeout/refusal/parser failure 等失败分母；
4. 把 PPL、retriever score、judge score 或 verbal confidence 当无条件概率；
5. 把 pass-at-k、oracle、best-of-$N$ 当实际 selected success；
6. 把引用存在当事实正确，或把语义相似当来源支持；
7. 把 benchmark 高分写成无污染、无偏或安全；
8. 使用未授权数据/系统，保存真实秘密、凭据或可复用攻击载荷；
9. 只发布成功均值，不保存 per-unit raw traces、负结果与选择过程；
10. Card/标准/厂商报告被当作独立复现或认证。

# 70.4 指令适配与参数高效微调 MOC

> [!abstract] 卷终目标
> 从消息序列化和 token loss 开始理解 SFT，再以数据、参数、显存、函数与证据五本账比较 full fine-tuning、LoRA/QLoRA、Adapter/Prompt/Prefix/IA3 与参数合并。学习者最终能从 messages 追到 loss，从 base 追到 adapter/merged artifact，并独立判断“参数高效”究竟高效在哪个单位上。

## 一、课程主线

指令适配不是把“聊天数据”喂给模型这么简单。它是四次明确选择：

1. 消息如何编译为 token 条件事件；
2. 哪些 shifted tokens 进入监督风险；
3. 哪些参数/状态允许变化；
4. 最终比较的是参数、显存、时间、函数还是任务表现。

~~~mermaid
flowchart LR
    M["messages + tools"] --> T["template + tokenizer"]
    T --> L["labels + relation + loss mask"]
    D["instruction data + mixture"] --> L
    L --> F["full / frozen / PEFT update"]
    F --> A["adapter or tuned checkpoint"]
    A --> G["merge / quantize / serve"]
    G --> E["new + old + OOD + safety evidence"]
~~~

## 三、五本贯穿账

| 账本 | 必须记录 | 不允许的替代 |
|---|---|---|
| 序列账 | messages、template、IDs、generation start、parser | 只写 system prompt |
| 目标账 | labels、relation、loss mask、global numerator/denominator | 只写 SFT epochs |
| 参数账 | base、trainable set、LoRA/PEFT config、merge state | 只写 trainable 百分比 |
| 系统账 | storage/compute dtype、grad/optimizer/activation/peak、latency | 用 4-bit 或 rank 代替总显存 |
| 证据账 | new/old/OOD/safety、selection/search、CI、失败运行 | 只报平均 winner |

## 五、卷终能力

通过本卷意味着能：

1. 手工把 messages 编译为训练/推理 IDs 并验证 prefix equality；
2. 写 SFT 的 inputs、labels、relation、loss mask 与 global $N/D$；
3. 从 task draws 推到 assistant effective-target shares；
4. 分离 trainable count、parameter drift、functional drift 与 forgetting；
5. 推导 LoRA 两因子梯度、rank、参数量和 merge；
6. 写 QLoRA 的 storage/compute/optimizer/activation/temporary 总账；
7. 从计算图区分 Adapter、Prompt、Prefix、IA3 与 LoRA；
8. 手算 soup、task arithmetic、TIES，并用置换反例说明坐标边界。

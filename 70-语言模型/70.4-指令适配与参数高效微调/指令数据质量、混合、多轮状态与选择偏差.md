# 指令数据质量、混合、多轮状态与选择偏差

> [!abstract] 一句话结论
> 指令数据不是 prompt-response 行数，而是 task ancestor、template、conversation、turn、target 与来源主体构成的层级分布。所谓高质量必须相对目标和标注协议定义；生成、过滤和选择同时会改变覆盖与偏差。

## 一、定义一个可审计 instruction example

最小记录可写成：

$$
e=(a,\tau,u,M,Y,z),
$$

其中：

- $a$：ancestor task/dataset/source；
- $\tau$：template 与语言/风格变体；
- $u$：conversation 或用户主体；
- $M$：消息序列；
- $Y$：被监督的 assistant/tool targets；
- $z$：许可、teacher、过滤、质量、安全和 provenance metadata。

同一 ancestor task 可展开成多个 templates；同一 conversation 有多个 turns；一个 turn 有不同 token 数。因而：

$$
\#\text{tasks}\ne
\#\text{templates}\ne
\#\text{examples}\ne
\#\text{effective targets}.
$$

把它们都叫“数据量”会掩盖重复与权重。

## 二、质量不是一个客观标量

先声明目标 $U$，再定义质量维度。例如：

| 维度 | 可观察 proxy | 常见误写 |
|---|---|---|
| instruction 可执行性 | 标注者能否理解并完成 | 语法流畅=任务清楚 |
| response 正确性 | reference/tool/human verification | teacher 自信=正确 |
| helpfulness | 面向明确用户目标的 rubric | 长=有帮助 |
| safety | threat-model 下的违规/过拒 | 不含敏感词=安全 |
| diversity | semantic/task/template cluster coverage | 字符不同=独立 |
| provenance | source/author/rights/teacher/version | URL 可访问=可训练 |

可定义多维向量 $q(e)$，而不是先压成一个 universal score。若必须排序，应公开 aggregation：

$$
Q_w(e)=\sum_jw_jq_j(e),
$$

并报告改 $w$ 或阈值后的 sensitivity。

## 三、层级抽样与有效 target 份额

若先抽 task $a\sim\pi$，再抽 template $\tau\sim q(\tau\mid a)$、conversation $u$、turn $k$，最终每 target 的质量还受长度与 loss mask 影响。

域 $g$ 的 effective-target mass 近似为

$$
E_g
\propto
\pi_g
\mathbb E[L_g]
\mathbb E[m_g],
$$

归一后：

$$
e_g=
\frac{\pi_g\bar L_g\bar m_g}
{\sum_h\pi_h\bar L_h\bar m_h}.
$$

所以 task-uniform 不等于 conversation-uniform，更不等于 assistant-token-uniform。必须至少并列：

- ancestor task draws；
- unique conversations；
- assistant turns；
- model tokens；
- effective targets；
- synthetic teacher/API calls；
- compute 与 repeats。

## 四、模板扩增不等于独立任务扩增

一个 task 用 20 个模板生成 20 份表面不同文本，语义变量仍可能相同。若 train/test 只按 rendered example 随机划分，同一 ancestor/template family 可跨 split，造成模板泄漏。

正确 split unit 依 estimand：

- 测同任务新实例：按 instance split；
- 测新模板：template family held out；
- 测新任务：ancestor task held out；
- 测新域/语言：domain/language held out；
- 测新时间：按 source timestamp split。

“unseen task”必须给 ancestor graph 与 exclusion rule，不能只检查最终字符串不重复。

## 五、多轮 conversation 的状态与权重

多轮样本的 later response 依赖历史。若把每个 turn 独立复制成训练样本：

$$
(M_{\le1},y_1),\ (M_{\le2},y_2),\ldots,
$$

早期 turns 会在多个前缀中重复出现；长 conversation 获得更多抽样机会和上下文 token。

需要决定：

1. 一 conversation 只抽一个 turn，还是所有 turns；
2. loss 计所有 assistant messages 还是仅最后一条；
3. 截断后怎样保证 role/tool state 合法；
4. privacy/deletion 以 message、turn、conversation 还是 user 为单位；
5. 跨 turn 矛盾、纠错与引用如何标注。

若目标是“在真实长对话中维持状态”，把所有 turns 打散成单轮 QA 会改变任务，而非无害清洗。

## 六、Synthetic instruction 的反馈回路

Self-Instruct 类管线可概括为：

$$
\text{seed}
\xrightarrow{\text{teacher }G}
\text{candidates}
\xrightarrow{F}
\text{selected}
\xrightarrow{\text{SFT}}
\text{student}.
$$

如果 student 或其后代又成为下一轮 teacher，得到闭环。风险包括：

- teacher 的事实错误和拒答风格被复制；
- generator 更易产生它熟悉的任务，coverage 收缩；
- filter 若由同族模型评分，会偏好同风格；
- semantic dedup 删除少数表达、保留主流模板；
- API/model silent update 改变数据版本；
- synthetic labels 与 benchmark answers 重合。

“几乎无需人工标注”不等于无需人工审计；人仍定义 seed、prompt、filter、rubric 与 deployment target。

## 七、选择偏差：只看 kept data 不够

设候选分布为 $P(e)$，保留事件 $S=1$ 的概率为 $a(e)$。最终训练分布：

$$
Q(e)=\frac{P(e)a(e)}{\mathbb E_P[a(E)]}.
$$

如果 quality scorer 对长、正式、英语、百科风格更高，训练模型会偏向这些风格。最终数据“平均质量分更高”只证明按该 scorer 选择成功，不证明对未见用户目标更好。

应保存：

- candidate/kept/rejected manifests；
- score、threshold、reason 与 scorer version；
- 人工 gold 的 false retain/false reject；
- task/language/length/source/safety 切片；
- 边界样本与 appeal/re-review；
- selection 前后分布和有效 target 份额。

## 八、小而精与大而杂：怎样正确比较

LIMA 等工作提示少量精选数据可能有很强效果；FLAN/Flan Collection 提示任务规模、混合与模板也重要。二者不是逻辑矛盾，因为它们改变了：

- base checkpoint 能力；
- data purpose 与 task coverage；
- response curator/teacher；
- train targets/FLOPs；
- evaluation 与 human preference；
- selection budget 与 rejected pool。

公平实验应构造 quality–quantity frontier，而不是只选两个点：

$$
\text{performance}=f(N_{\text{unique}},T_{\text{eff}},Q,\text{coverage},\theta_0).
$$

至少比较等 examples、等 effective targets、等 FLOPs 三个预算，并把数据生成/人工筛选成本另账。

## 九、污染、重复与来源继承

指令数据可能把公开 benchmark 的题目、答案、rationale、翻译或模板重新包装。应在 ancestor 和 rendered 两层去重：

$$
\text{overlap}
=\text{ancestor identity}
\cup\text{text similarity}
\cup\text{label/rationale match}.
$$

若 synthetic teacher 曾通过 API 访问未知训练数据，无法证明其输出无 benchmark 记忆；只能记录 teacher/version、检测器与不可观察边界。

来源许可、隐私与删除也会从 ancestor 传到 templates/instances/checkpoints，回链[[预训练语料来源、许可、隐私与文档单位合同]]。

## 十一、最小数据卡

一个 instruction 数据版本至少记录：

- ancestors、licenses、user/annotator/teacher provenance；
- template family、language、task taxonomy；
- message schema、tool schema、turn unit；
- candidate/kept/rejected counts；
- unique conversations、turns、tokens、effective targets；
- task/template/conversation/target mixtures；
- quality/safety rubric、annotator agreement、scorer calibration；
- dedup/contamination detectors；
- train/validation/test split unit；
- deletion key 与 downstream run impact。

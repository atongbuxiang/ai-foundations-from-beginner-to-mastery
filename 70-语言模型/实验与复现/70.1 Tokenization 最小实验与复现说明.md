# 70.1 Tokenization 最小实验与复现说明

> [!abstract] 实验结论
> 标准库脚本通过 9 项确定性检查：NFC canonical equivalence、NFKC compatibility 折叠、normalization 幂等、BPE merge-rank 分叉与 overlap、WordPiece greedy dead end、Unigram marginal/采样概率及任意 byte round-trip。20,000 次固定 seed 的 Unigram 抽样最大绝对误差为 **0.000942**，远低于预注册阈值 0.015。

## 一、问题与可证伪预期

| ID | 问题 | 通过条件 |
|---|---|---|
| H1 | 预组合/分解 `é` 的 NFC 是否一致？ | normalized string 相等 |
| H2 | NFKC 是否折叠圈号与全角？ | `①→1`、`Ａ→A` |
| H3 | 四种 normalization 是否幂等？ | 全部固定样例通过 |
| H4 | BPE 仅换 merge rank 是否改变 `abc`？ | `[ab,c]≠[a,bc]` |
| H5 | `aaaa` 的非重叠 merge 是否为 `[aa,aa]`？ | exact equality |
| H6 | WordPiece greedy 是否可能失败而全局路径存在？ | greedy=None，DP=`[a,##bc]` |
| H7 | `ab` 的 Unigram marginal 是否为 0.32？ | error $<10^{-12}$ |
| H8 | 温度化采样是否匹配 exact target？ | max abs error $<0.015$ |
| H9 | 256-byte 基本码能否随机 round-trip？ | 1,000 组全部通过 |

## 五、实验图 2：局部路径规则

先看图回答：左图为什么只换 rank 就分叉，右图为什么 longest local match 不保证 global coverage？

![[00-知识库管理/_assets/plots/language-models/plot-tokenization-path-algorithms-v1.svg|900]]

> [!figure] 图 EXP-LM-701-02　BPE rank 与 WordPiece greedy 的构造性反例
> 左侧从同一 `abc` 基本序列得到两种 BPE 编码；右侧固定词表 `{a,ab,##bc}`，greedy 失败但 DP 找到路径。来源：标准库脚本直接计算。

**怎样读图**：左侧固定初始符号序列，只交换 merge rank，核对最终分词如何分叉；右侧先执行最长匹配，再用全局动态规划检查是否仍存在覆盖整串的合法路径。

**图没有证明什么**：两个构造反例只证明局部 rank/greedy 规则的算法边界，不比较 BPE 与 WordPiece 在真实语料、多语言、公平性或下游任务上的总体质量。

## 六、实验图 3：Unigram sampling oracle

先看图回答：经验频率是否在抽样误差内贴合温度化后的 exact path probability？

![[00-知识库管理/_assets/plots/language-models/plot-tokenization-unigram-sampling-v1.svg|900]]

> [!figure] 图 EXP-LM-701-03　Unigram 两条路径的目标与经验概率
> 绿柱为 exact $q_{0.5}$，蓝柱为 20,000 次固定 seed 抽样；两条路径误差相等且方向相反，因为概率和均为 1。
> **数据来源：**本图由本卷确定性实验脚本生成，并与同目录 results/CSV 或脚本内固定数组同源；未特别标注的结构只承担教学排版。

**怎样读图**：先从原 path probability 开方并归一化，再与频率比较；不能把 $\alpha=.5$ 的 target 误当 $\alpha=1$ posterior。

**图没有证明什么**：两路径离散样例不能证明大型 tokenizer sampling 的速度、数值稳定或下游正则收益。

## 八、可复现边界

Python `unicodedata` 绑定解释器内置 Unicode 数据，脚本已把版本写入结果；升级 Python 后 normalization 表可能更新，应把差异作为数据/tokenizer 版本变更。抽样只要求带容差概率一致，不要求跨随机数实现的逐 draw bitwise identical。

此实验验证 toy algorithm 的定义与反例，不验证任何真实 tokenizer 的多语言质量。规模结论必须进入[[Tokenizer 评估、多语言公平、安全与证据地图]]的预算匹配协议。

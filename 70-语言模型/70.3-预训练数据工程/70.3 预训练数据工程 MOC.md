# 70.3 预训练数据工程 MOC

> [!abstract] 卷终目标
> 把来源、许可、解析、过滤、去重、污染、混合、packing、训练路径、版本和有效 token 连成可审计数据管线。学习者不再把“1T tokens”视为自解释数字，而能从一次 loss event 逆向追到 tokenizer、document、transform、source 与治理证据。

## 一、为什么这一卷是模型理论的一部分

预训练优化的并不是抽象的“互联网分布”，而是数据管线产生的经验分布。过滤器决定谁被保留，去重器决定谁获得多少曝光，mixture 决定域权重，packing 决定 relation 与 loss，curriculum 决定梯度的有序路径。因此，数据工程不是训练前的清洁杂务，而是在定义风险函数、样本权重与可识别结论。

~~~mermaid
flowchart LR
    S["source asset / capture"] --> P["parse + language ID"]
    P --> F["quality / rights / privacy filter"]
    F --> D["exact + near dedup"]
    D --> C["benchmark cutoff + contamination audit"]
    C --> M["mixture + curriculum"]
    M --> K["tokenize + pack"]
    K --> L["loss events / effective targets"]
    L --> V["run + checkpoint provenance"]
    V -. deletion / audit .-> S
~~~

## 三、四条贯穿线

| 贯穿线 | 起点 | 终点 | 必须守住的不变量 |
|---|---|---|---|
| 对象线 | source asset | loss event | 每次切分、规范化和抽样都声明单位 |
| 分布线 | source population | training target share | selection、dedup、mixture 与重复曝光均可量化 |
| 边界线 | document / benchmark / time | attention、loss、evaluation | 不让物理拼接或公开时间偷换逻辑隔离 |
| 证据线 | source record | checkpoint / claim | ID、hash、version、reason 与 agent 可正反向遍历 |

## 五、卷终门

同一“token 数”必须能追溯到文档、tokenizer、去重版本、mixture 权重与 loss mask；无法追溯的规模数字不进入因果比较。

通过本卷意味着能独立完成以下任务，而不是仅浏览文件：

1. 从 source distribution 推出过滤后的 selected distribution；
2. 证明 MinHash 概率恒等式，并区分 LSH candidate、exact pair 与 cluster；
3. 用 base rate、recall、FPR 解释污染 detector 阳性；
4. 分别计算 document、token、effective-target 与 compute share；
5. 手写 packing 的 relation、position 与 loss contract；
6. 用更新不交换解释 curriculum 路径依赖；
7. 从 loss event 反向追溯到 source，并输出删除影响报告。

# 解析、语言识别、质量过滤与数据偏差

> [!abstract] 一句话结论
> 数据过滤不是从“脏分布”恢复一个客观“干净分布”，而是带阈值、代理标签和错误率的选择机制。它改变语言、群体、文体、主题与难度的联合分布；因此每个 retained corpus 都必须与同版本 rejected ledger、切片保留率和反事实样例成对保存。

## 一、网页到文本的管线

一个典型但非唯一的 web pipeline：

$$
\text{WARC bytes}
\to\text{decode}
\to\text{DOM/parser}
\to\text{main-text extraction}
\to\text{language ID}
\to\text{quality/safety filters}
\to\text{dedup}
\to\text{documents}.
$$

每步都可能产生三种输出：`keep`、`reject(reason)`、`quarantine(uncertain)`。只保存 keep 会让错误不可测；只存最终计数又无法知道两个规则共同删除了谁。

### 顺序通常不可交换

令 $F$ 是 boilerplate filter，$D$ 是 dedup。一般

$$
F(D(\mathcal C))\ne D(F(\mathcal C)).
$$

先去重可能让垃圾模板与正文形成 cluster，并依代表规则删除好样本；先抽正文又改变 shingles 和重复关系。语言识别在正文抽取前后也可能不同。Pipeline DAG 和顺序属于数据版本。

## 二、解析失败不是随机缺失

主文本抽取器往往更擅长常规新闻/博客 HTML，可能漏掉：

- JavaScript 渲染页面与交互式文档；
- 表格、公式、alt text、代码块与脚注；
- 非标准编码、竖排或右到左脚本；
- 论坛嵌套引用与对话角色；
- PDF/OCR 中的多栏、页眉和断词。

若解析成功事件为 $R=1$，最终分布条件于 $R=1$。当 $R$ 与语言/域/页面结构相关，missingness 不是 MCAR。必须按 MIME、语言、域名、模板和长度报告 parse success，而非只给总体 93%。

## 三、语言识别是带不确定性的分类器

Language ID 常输出 score $p_\phi(\ell\mid d)$，规则可能为

$$
\widehat\ell(d)=\arg\max_\ell p_\phi(\ell\mid d),
\qquad \text{keep if }p_\phi(\widehat\ell\mid d)\ge\tau.
$$

这在短文本、代码切换、近缘语言、转写体、专名/公式和低资源语言上容易失效。固定阈值也不保证各语言 precision/recall 相同。

建议保存 top-$k$ labels/scores、model/version、text length 与 `undetermined`；在人工标注样本上按语言画 confusion matrix，并把 LID false reject 纳入数据预算。若只保存 hard label，后续无法在新阈值下重算。

## 四、质量到底是什么随机变量

常见信号：

- 字符/词重复、标点/数字比例、平均词长；
- 句子终止、长度、异常 Unicode；
- blocklist/规则；
- n-gram 与参考语料相似度；
- classifier 对“高质量”参考集的概率；
- domain/URL reputation 或链接结构。

这些是 proxy，不是自然真值。若 reference positive 多为百科、新闻、书籍，classifier 可能把方言、口语、少数群体文本、创作体、代码混文判为低质。`quality_score=0.92` 必须附“谁标注、以什么标准、在哪个分布校准”。

## 五、选择后分布的严格表达

设原文档 $D\sim P$，过滤器随机/确定性选择 $S\in\{0,1\}$，保留概率为 $a(d)=P(S=1\mid D=d)$。保留分布为

$$
Q(d)=P(D=d\mid S=1)
=\frac{P(d)a(d)}{\mathbb E_P[a(D)]}.
$$

若 $a(d)$ 非常数，$Q\ne P$。对群组 $G=g$ 的保留率

$$
r_g=P(S=1\mid G=g)
$$

决定群组比例变化：

$$
Q(G=g)=\frac{P(G=g)r_g}{\sum_hP(G=h)r_h}.
$$

### 手算

原始 A/B 各 50%，保留率分别 80%/40%。保留集 A 比例为

$$
\frac{0.5\times0.8}{0.5\times0.8+0.5\times0.4}=\frac23.
$$

总体保留率 60% 看似中性，群体构成却从 50/50 变为 67/33。

## 六、Filter 的 precision/recall 与代价

令真正不适用事件为 $Y=0$，filter reject 为 $\hat Y=0$：

- false positive（误删）：损失有价值、稀有或代表性文本；
- false negative（漏留）：引入垃圾、隐私/安全风险或重复；
- 阈值变化在二者之间做 trade-off。

极低基率风险下，即使 classifier specificity 很高，自动 reject 的阳性预测值也可能不够；反之，过严 filter 可显著削弱低资源覆盖。高风险类别应采用分层 review/隔离，不必强迫单一阈值解决所有目的。

## 七、如何比较 C4、Gopher 与 RefinedWeb 配方

不要按“规则更多”“剩余 token 更少”排名。比较表至少含：

| 轴 | 必须对齐/记录 |
|---|---|
| raw source | crawl IDs、日期、语言与下载范围 |
| parser | HTML/WET/OCR、正文抽取版本 |
| heuristics | 公式、阈值、顺序与 reject reason |
| learned filters | positives/negatives、model、calibration |
| dedup | unit、shingle、threshold、representative |
| output | documents、raw bytes、tokenizer-specific tokens、切片 |
| model evidence | 参数/FLOPs、训练 tokens、optimizer 与 evaluation |

某论文在自身对照中发现更好模型结果属于 `E`；“此 filter 定义了语言质量”不是 `I/T`。C4 的后续审计尤其说明 retained/rejected 内容与来源分析不可省略。

## 九、最小过滤实验

1. 固定一批 raw records 与人工 stratified sample；
2. 对每个 stage 输出 `(input_id, decision, score, reason, config_hash)`；
3. 预注册总体和语言/域/长度/模板/群体切片的 retention、precision、recall；
4. 扫 threshold，画质量 proxy 与覆盖率 frontier；
5. 人工盲审 keep/reject 边界样本；
6. 交换两个 filter 顺序，量化非交换差异；
7. 用相同训练 FLOPs 做 downstream 对照，报告 selection/search cost；
8. 保存 rejected hashes/安全 metadata，避免重新摄入，同时遵守最小化与访问控制。

## 十、本节出口

你应能从 selection indicator 推导保留后分布，手算群体比例变化，解释 LID/quality score 的 calibration 与阈值边界，并设计 retained/rejected 双账。下一节[[精确去重、MinHash、LSH 与近重复检测]]把“重复”从直觉变为集合相似度与概率候选检索。

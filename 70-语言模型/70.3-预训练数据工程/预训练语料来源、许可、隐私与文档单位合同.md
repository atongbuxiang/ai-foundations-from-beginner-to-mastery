# 预训练语料来源、许可、隐私与文档单位合同

> [!abstract] 一句话结论
> “训练数据”不是一袋无来源文本，而是一条从网页/仓库资产、抓取记录、解析文档、过滤实例到 token/loss 事件的派生链。可下载性、抓取协议、内容许可、个人隐私和特定用途是不同判断层；只有逐层保存证据、责任人和版本，数据规模与合规主张才可审计。

> [!warning] 非法律意见
> 本节教授数据与证据建模，不判断某一具体训练用途在某法域是否合法。真实项目应由具资格的法律、隐私、安全和领域人员结合最新条款与事实审批。

## 一、先把六种对象分开

一条看似简单的网页文本，在管线中至少经历：

1. **source asset**：某 URI、仓库文件、数据库行或出版物中的原始资产；
2. **capture record**：在时间 $t$ 通过某协议得到的 bytes、HTTP headers 与 WARC metadata；
3. **parsed document**：特定 parser 从 capture 提取的正文、标题、语言和结构；
4. **selected example**：经过许可/隐私/质量/去重规则后保留的实例；
5. **token sequence**：指定 normalization、tokenizer 与边界编译出的 IDs；
6. **loss events**：packing、shift 与 loss mask 后真正进入 $N,D$ 的预测位置。

它们不是同一个 id。建议为每层使用内容寻址 hash，并保存派生边：

$$
E_0\xrightarrow{\text{capture }a_1}E_1
\xrightarrow{\text{parse }a_2}E_2
\xrightarrow{\text{select }a_3}E_3
\xrightarrow{\text{tokenize }a_4}E_4.
$$

若只保存最终 `.bin` shard，无法回答某 token 来自哪一页、何时抓取、为何保留，也无法执行有范围的删除或重建统计。

## 二、WARC 提供什么，不提供什么

WARC 可记录 response/request、target URI、时间、record id、payload digest、metadata、duplicate/derivation relation。它帮助回答“抓到了什么”和“哪条记录由哪条记录派生”。

它不自动提供：

- 网页正文的正确主内容边界；
- 作者、说话者或隐私主体身份；
- 内容的版权/许可结论；
- 训练用途的授权；
- 抓取后条款或删除请求的变化；
- parser 是否丢失表格、alt text、代码或语言。

WET/plain-text 是对 WARC payload 的一次有损 transformation，不应覆盖 raw capture。保留 raw/parsed 双层 hash，才能在 parser 更新时重放并做差分。

## 三、四层权利与治理账

### 1. 访问与抓取层

记录 crawler identity、robots snapshot、rate policy、API/service terms、身份认证与访问时间。`robots.txt` 是抓取协议的一部分，不是全球统一的内容许可或隐私同意书。

### 2. 内容权利层

记录内容作者/权利人线索、显式 license、attribution、share-alike/noncommercial 等条件、上游 asset licenses 与不确定性。聚合数据集顶层写 `Apache-2.0` 可能只覆盖管线代码或新增 metadata，不能机械覆盖其收录的第三方文本。

### 3. 人与隐私层

公开可见不等于当事人合理预期其文本进入大模型。至少建立 PII、敏感属性、未成年人、医疗/财务/定位、私密通信、可删除性与重识别风险分类。匿名化也不是一次 regex 后永久安全；上下文与模型记忆可能重新连接身份。

### 4. 用途与法域层

研究、商业训练、开放发布、内部评测、再分发和生成式输出可能触发不同义务；适用法域和机构政策也会变化。每个 dataset release 应保存 `intended_use`、`prohibited_use`、审批人、日期和复审条件。

> [!important] “open”至少有三种不同含义
> open access（能下载）、open source（代码许可）与 open content/data license（内容/数据库权利）不能互换。若来源字段未知，应写 `unknown/needs-review`，不能为方便训练填成 `permissive`。

## 四、什么算一个 document

Document 是统计与治理单位，不一定等于文件：

| 来源 | 可能单位 | 主要边界风险 |
|---|---|---|
| 网页 | URL response、正文 article、section | 模板/评论混入；分页重复 |
| 论坛 | thread、post、comment | 多作者与引用重复 |
| 代码仓库 | repo、file、function | license inheritance、vendor copy |
| 书籍/PDF | volume、chapter、page | 页眉/OCR、作品整体权利 |
| 对话 | conversation、turn | 多主体隐私与上下文泄漏 |

文档单位影响：去重 cluster、train/validation split、sample weighting、packing 边界、删除粒度和 exposure 统计。若把每段当独立文档，高频长文章可能获得更多抽样权；若整站一个文档，又可能超大且不可局部删除。

定义原始资产 $u$ 经 segmentation $g$ 产生 documents：

$$
g(u;v_g)=(d_1,\ldots,d_{K(u)}).
$$

版本 $v_g$ 属于数据集定义。报告“100M documents”必须同时报告 $g$、长度分布和 parent asset 数。

## 五、数据分布从哪里来

设网络/仓库世界中的潜在资产分布为 $P_U$，crawler 的 inclusion probability 为 $c(u)$，parser 成功概率为 $r(d\mid u)$，保留概率为 $s(d)$。训练前文档分布近似为

$$
Q(d)\propto P_U(u(d))\,c(u(d))\,r(d\mid u(d))\,s(d).
$$

$Q$ 不是“互联网分布”：链接发现、robots、抓取优先级、语言识别、过滤与去重都做了选择。后续若按域权重 $\pi_g$ 重采样，模型看到的是另一分布。数据卡应把每一层 selection mechanism 写出来，而不只列来源域名。

## 六、最小记录 schema

```yaml
asset_id: content/record hash
source_uri: ...
captured_at: ...
warc_record_id: ...
raw_payload_digest: ...
parser_version: ...
document_parent_and_offsets: ...
language_label_and_score: ...
rights_evidence: {source_terms, content_license, attribution, uncertainty}
privacy_review: {pii_class, action, reviewer, deletion_key}
transforms: [decode, extract, normalize, redact, filter, dedup]
selection_reasons: ...
tokenizer_hash: ...
token_count_and_loss_eligibility: ...
approvals_and_expiry: ...
```

敏感原文与公开 metadata 应采用分级访问；“为了 provenance 保存一切”不能凌驾于 data minimization 和删除义务。

## 八、最小验收门

- 随机抽 20 个最终 training samples，能回到 raw capture 与 source URI；
- parser 更新后能重放并报告字段/文本差异；
- 顶层 dataset license 与每个 ancestor asset 分开；
- 公开、抓取允许、内容许可、用途批准不共用一个布尔值；
- document segmentation 版本化，并能解释样本权重；
- 删除请求能定位派生 document、token shard 与 checkpoint 影响范围；
- 未知/冲突证据进入 quarantine，而非默认保留。

## 九、本节出口

你应能把任意训练 token 回溯为“资产—抓取—解析—选择—token—loss”链，并解释权利、隐私和文档单位为什么不能从文件后缀或平台标签推断。下一节[[解析、语言识别、质量过滤与数据偏差]]研究这些 transformation 如何系统性重塑训练分布。

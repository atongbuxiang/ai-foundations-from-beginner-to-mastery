# 能力—行为—系统评估协议与证据地图

> [!abstract] 一句话结论
> 可信评估不是更多 benchmark 的堆叠，而是对能力、解码行为、工具系统和在线结果做可干预分层：冻结比较对象，用 oracle 替换定位瓶颈，保留每个分母与失败，再以不确定性、成本和决策阈值收口。

## 一、四层对象

1. **能力层**：固定 history 下模型是否给正确信息较高概率，或在适当提示下能否完成；
2. **行为层**：固定 decoder、prompt、sample budget 后实际输出分布；
3. **系统层**：retrieval/tools/parser/guardrail/scheduler 后的端到端轨迹；
4. **部署层**：真实用户、时间、负载、反馈和政策下的效用/风险。

一次 top-1 accuracy 主要测特定行为，不等于潜在能力；gold-context 成功也不等于实际 RAG 成功；离线系统成功不等于在线用户效用。

## 二、用 intervention 定位，而非硬拆加法

设完整系统结果 $Y=f(M,D,R,T,J,\epsilon)$。可以做：

- raw/fixed prompt；
- 多 prompt 或 oracle prompt；
- greedy vs sampling/search；
- normal retrieval vs gold context；
- tool off/on 或 oracle tool output；
- parser/constraint off/on；
- human vs model judge；
- offline fixed workload vs online trace。

每次只替换一层，比较 paired outcome。不要假设总增益可加：

$$
\Delta_{\rm total}
\ne\Delta_M+\Delta_D+\Delta_R+\Delta_T
$$

通常因为交互作用存在。例如强模型可能更会利用检索，也可能更会绕过证据。

## 三、六级 oracle ladder

| 级 | 替换 | 主要识别 |
|---|---|---|
| O0 | closed-book/fixed decoder | 参数与基本行为基线 |
| O1 | 多样本 oracle selection | 候选覆盖上界 |
| O2 | gold prompt/template | prompt/format 损失 |
| O3 | gold context/evidence | corpus/retrieval/context 损失 |
| O4 | gold tool result/parser | tool planning/execution/format 损失 |
| O5 | human fact/judge | 自动 metric/judge 测量误差 |

Oracle 不是部署方案，而是诊断干预。不同 oracle 可能改变输入分布，必须说明其可比性与成本。

## 四、Metric tree 而非总分

顶层 decision 可由多项约束组成：

$$
\text{ship}(c)=
\mathbf1[
Q(c)\ge q_0,\ 
R_{\rm safety}(c)\le r_0,\ 
L_{99}(c)\le \ell_0,\ 
C(c)\le c_0].
$$

保留 metric tree：

- capability/task quality；
- robustness/calibration/coverage；
- factuality/grounding/attribution；
- safety/fairness/privacy；
- TTFT/TBT/goodput/reliability；
- token/energy/money/human cost。

一个加权总分会隐藏 veto 条件与权重。若必须综合，应公布归一化、权重、敏感性与被支配配置。

## 五、最小预注册

1. 决策与 estimand；
2. 对象版本和唯一干预；
3. target population、sampling/cluster unit；
4. benchmark/splits/time cutoff/contamination；
5. prompts/decoder/tools/judge；
6. primary/secondary metrics 与 failure denominators；
7. sample size、seeds、CI、multiplicity；
8. compute/latency/cost budget；
9. threshold/non-inferiority margin；
10. exclusion、stopping、missing、adjudication；
11. artifacts 与复现命令。

预注册不禁止探索；它把 confirmatory 与 exploratory 分开。

## 六、最小数据表

每一行保存到独立 unit/run 粒度：

| 字段族 | 内容 |
|---|---|
| identity | task/example/user/request/run IDs、timestamp |
| config | model/tokenizer/template/decoder/retriever/tool/judge hashes |
| input | raw prompt、token IDs、references、source snapshot |
| output | raw token/text、samples、finish/failure、tool/citation trace |
| score | parser result、per-metric score、claim/judge labels |
| resource | tokens、calls、latency、memory、cost |
| audit | seed、worker/hardware、code commit、human annotator/adjudication |

只保存聚合 CSV 会失去重新评分、换 judge 与失败分析能力。

## 七、比较与决策

同一题上比较 A/B，用 paired difference；同用户/文档按 cluster；多 seed 是嵌套重复。报告 effect、CI 与 threshold：

$$
\Delta=\theta_A-\theta_B,\qquad
CI_{1-\alpha}(\Delta).
$$

非劣检验例：质量下界大于 $-\delta$，同时安全/延迟硬约束通过。统计显著不等于实际重要；区间跨过业务阈值时结论应为不确定，而非强行选赢家。

上线后监控的数据分布与离线 benchmark 不同。必须计划 drift、delayed labels、feedback selection 与 incident review；这些生产治理在 70.9 展开。

## 八、图解：从能力探针到上线决策

**读图问题**：同一模型的能力、解码行为、RAG/tool 系统和在线结果怎样用 oracle 干预逐层定位，最终又如何在多指标硬约束下做决策？

> **生成：**本库汇总 LM57—63 的对象、指标和诊断协议绘制；箭头表示评估依赖，不声称真实因果效应已被识别。

**怎样读图**：先纵向区分能力—行为—系统—部署，再横向用 oracle 一次替换一层；每个 leaf metric 回到 per-unit artifact、区间和成本，只有所有预注册 hard gates 通过才进入决策。

**图没有证明什么**：层级图不能保证干预无分布改变或交互作用，也不能用静态 benchmark 替代线上监控；完整 artifact 只使结论可审计，不自动使样本代表、指标有效或系统安全。

## 九、常见错误与出口标准

错误包括：能力等于 top-1；oracle 当产品；增益硬加；总分隐藏安全 veto；只存均值；test 调参；显著性当重要性；上线后无 drift/incident 计划。

完成本节后，应能为一个 RAG/tool/agent 系统写四层 estimand、oracle ladder、metric tree、per-unit schema、paired/cluster CI 与 ship/no-ship 规则，并明确仍留到 70.9 的生产风险。

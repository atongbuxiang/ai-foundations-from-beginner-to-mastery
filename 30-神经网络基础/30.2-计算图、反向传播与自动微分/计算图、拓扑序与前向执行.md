# 计算图、拓扑序与前向执行

> [!abstract] 本章主问题
> 计算图不是一张网络结构插画，而是一个可执行合同：每个节点保存有类型的值，每个算子声明输入、输出和局部规则，有向边表示数据依赖。对无环图，任意拓扑序都能正确前向执行；分支、共享参数、缓存和状态必须显式记录，后续反向传播才能忠实地对“实际执行的程序”求导。

## 课程位置与两遍学习路线

- **承接什么：** 30.1 已把网络写成逐层函数复合，但“按公式顺序计算”还没有被形式化为可调度、可缓存、可求导的程序；
- **本页解决什么：** 把一个真实训练目标拆成 typed values、local operations、data dependencies 与 execution order；
- **后续为何需要：** NN-10 为每个局部算子配导数作用，NN-11 沿逆拓扑序组合它们，NN-12 再把 affine 节点变成矩阵梯度公式。

**第一遍只执行 forward。** 逐节点写出父节点、shape、数值与是否需要缓存；只要能判断一个顺序是否合法并得到同一个 loss，就先不要急着求导。

**第二遍再审计程序语义。** 加入 fan-out、共享参数、broadcast、random/state、alias 与 mutation，区分数学 DAG、实际 trace 和底层 storage。

### 问题链

1. 一个数学表达式怎样拆成局部可执行算子而不改变函数？
2. 哪些节点是真正输入、参数、常量、中间值和状态？
3. 为什么拓扑序可以不唯一，输出却应保持一致？
4. 同一个 $W$ 同时进入 prediction 与 regularization 时，是复制了参数还是产生 fan-out？
5. backward 必须保存哪些 forward 证据，哪些可以安全重算？

> [!check] 第一遍停靠线
> 若你能为贯穿算例列出一条合法拓扑序，算到 $L=5.25$，并指出 $W$ 的两条 outgoing paths，就可以进入局部微分；Kahn 算法、随机状态与 mutation 留到第二遍。

## 符号与对象账本

| 对象 | shape/类型 | 在 AI 训练程序中的角色 | backward 需要什么 |
|---|---|---|---|
| $X_\diamond,Y_\diamond$ | $2\times2$ | input 与 target | $X$ 用于 $\bar W$，$Y$ 通常不求梯度 |
| $W_\diamond,b_\diamond$ | $2\times2,1\times2$ | shared trainable parameters | 原值、shape 与调用次数 |
| $Z,R$ | $2\times2$ | prediction 与 residual | $R$ 给平方损失局部梯度 |
| $L_{\rm data},L_{\rm reg}$ | scalar | 两条 loss branches | 各自对共享参数的贡献 |
| $L$ | scalar | optimization objective | reverse seed $\bar L=1$ |

### 贯穿算例：一个带共享参数分支的训练图

后四页共用

$$
X_\diamond=\begin{bmatrix}1&2\\-1&1\end{bmatrix},\quad
W_\diamond=\begin{bmatrix}1&-1\\2&1\end{bmatrix},\quad
b_\diamond=\begin{bmatrix}0&1\end{bmatrix},\quad
Y_\diamond=\begin{bmatrix}4&1\\2&1\end{bmatrix},\quad \lambda=\tfrac12.
$$

执行

$$
Z=X_\diamond W_\diamond+\mathbf1b_\diamond,\quad R=Z-Y_\diamond,\quad
L=\tfrac12\|R\|_F^2+\tfrac\lambda2\|W_\diamond\|_F^2
$$

得到 $Z=\left[\begin{smallmatrix}5&2\\1&3\end{smallmatrix}\right]$、$R=\left[\begin{smallmatrix}1&1\\-1&2\end{smallmatrix}\right]$、$L_{\rm data}=3.5$、$L_{\rm reg}=1.75$、$L=5.25$。一条合法拓扑序是输入/参数 → matmul → bias add → residual → data loss，同时 $W$ → regularizer，最后两项相加。$W$ 是同一节点的 fan-out，不是两份独立参数。

## 核心公式七问：$L=\frac12\|XW+\mathbf1b-Y\|_F^2+\frac\lambda2\|W\|_F^2$

| 问题 | 本式的回答 |
|---|---|
| 目的 | 用一个最小训练任务同时暴露 affine path、loss path 与 parameter-sharing branch |
| 对象 | $X,Y,W,b$ 是不同角色；$Z,R$ 是中间值；$\lambda$ 是固定超参数 |
| 来路 | supervised squared error 加显式 weight-decay penalty |
| 步骤 | matmul 必须先于 bias add，$R$ 先于 data loss；regularizer 可与 prediction branch 并行 |
| 读法 | objective 对 $W$ 有数据拟合与正则化两条依赖路径 |
| 检查 | 所有加法两侧 shape 一致；最终两项均为 scalar；$\lambda=0$ 时正则分支消失 |
| 去路 | JVP/VJP 点积检验、fan-out adjoint 累加、dense backward 与 optimizer 更新 |

## 一、学习目标
1. 把计算图形式化为有向无环图与局部函数；
2. 区分 value node、operation node、parameter、constant 与 state；
3. 判断一个顺序是否为 topological order；
4. 用 Kahn 算法生成拓扑序并识别 cycle；
5. 手算带分支图的全部前向值；
6. 区分共享参数与复制参数；
7. 解释 broadcasting、reshape 和 reduction 为何也是算子；
8. 说明 training/eval、随机 mask 与 mutable state 如何进入语义；
9. 建立 backward 所需 cache；
10. 审计 dynamic control flow 与 in-place mutation。

## 二、从表达式到 DAG
考虑
$$
a=x_1x_2,\qquad b=\sin x_1,\qquad c=a+b,\qquad L=c^2.
$$
节点集合包含输入 $x_1,x_2$、中间值 $a,b,c$ 和输出 $L$；边为 $x_1\to a,x_2\to a,x_1\to b,a\to c,b\to c,c\to L$。它是 DAG，因为不存在沿有向边回到自身的路径。

局部算子分别是 multiply、sin、add、square。把整个 $L(x_1,x_2)$ 拆成局部函数不会改变函数，只改变计算与求导的组织方式。

## 三、节点类型不能只靠名字猜
| 类型 | 示例 | 是否训练更新 | 是否依输入改变 |
|---|---|---:|---:|
| external input | batch $X$ | 否 | 是 |
| parameter | $W,b$ | 是 | 否（一次 forward 内） |
| constant | $1/\sqrt d$ | 否 | 否 |
| intermediate | $Z,H$ | 否 | 是 |
| random value | dropout mask | 否 | 是，依 RNG |
| mutable state | BatchNorm running mean | 间接更新 | 可变 |

同样 shape 的 tensor 可能属于完全不同角色；反向、保存与复现规则也不同。

## 四、Topological Order
对 DAG，序列 $(v_1,\ldots,v_n)$ 是拓扑序，当每条边 $u\to v$ 都满足 $u$ 先于 $v$。上例可用
$$
(x_1,x_2,a,b,c,L)
$$
或 $(x_2,x_1,b,a,c,L)$；$c$ 不能先于 $a$ 或 $b$。

拓扑序通常不唯一，但若局部算子纯函数且精确算术，任何合法拓扑序给相同数学结果。浮点并行 reduction、随机数消费和 state mutation 会使实际程序还需更强执行合同。

## 五、Kahn 算法
1. 计算每个节点 indegree；
2. 把 indegree 为零的节点放入 ready queue；
3. 取出 ready node，输出它并删除其 outgoing edges；
4. 新的零 indegree 节点入队；
5. 若最终输出少于全部节点，剩余子图含 cycle。

时间复杂度为 $O(|V|+|E|)$。ready queue 的 tie-breaking 决定具体拓扑序，但不改变依赖合法性。

## 六、完整手算
取 $x_1=2,x_2=3$：
$$
a=6,\qquad b=\sin2\approx0.9093,\qquad c\approx6.9093,\qquad L\approx47.738.
$$
每个值只有在父节点就绪后计算。若后续需要 reverse mode，至少要保存 $x_1,x_2,a,b,c$ 或保存足以重构局部 derivative 的信息。

## 七、多输入算子与形状合同
矩阵乘法节点 $Z=XW$ 不只是一个圆圈；它声明
$$
X:[B,d_{in}],\quad W:[d_{in},d_{out}],\quad Z:[B,d_{out}].
$$
add、broadcast、transpose、reshape、slice、gather、reduce 都必须作为具有轴语义的操作。若把 reshape 当“没有数学意义”，反向时很容易把 layout 还原错。

## 八、Fan-out、Fan-in 与共享
当 $x_1$ 同时进入 multiply 和 sin，称为 fan-out。前向只需让两条支路读取同一值；反向必须把两条支路对 $x_1$ 的贡献相加。

同一参数 $W$ 在序列各位置或循环各步重复使用，是一个 value node fan-out 到多个 operation nodes，不是许多独立 $W_t$。最终 parameter gradient 必须聚合所有调用贡献。

## 九、Cache 与重计算
reverse mode 常需局部输入/输出：ReLU backward 需知道开关，matmul backward 需 $X,W$，softmax backward 需 probability。全部保存节省重算但耗 memory；只保存 checkpoint 可在 backward 重放中间区间。

cache 是执行策略，不改变数学函数，但会影响 memory、FLOPs、随机状态和数值复现。

## 十、Train/Eval 与随机图
Dropout 在 train mode 读取随机 mask，eval mode 通常是 identity；BatchNorm 在 train mode 读取 batch statistics 并更新 running state，eval mode 读取 stored statistics。故“同一代码模块”在不同 mode 下对应不同程序/函数。

要复现随机图，需记录 RNG algorithm、seed、counter/order 与 distributed sampling；只保存初始 seed 未必足够。

## 十一、Dynamic Control Flow
若程序含 `if x>0` 或依数据次数的 loop，实际执行图由输入决定。operator-overloading AD 常记录本次执行 trace；source transformation 可对控制流本身转换。求得的是已定义程序语义下的 derivative，不是所有未执行分支的平均。

离散 branch boundary 处可能不可微；“框架返回 gradient”不证明 classical derivative 存在。

## 十二、In-place Mutation 的危险
若 forward 后原地覆盖 $x$，而 backward 需要旧值计算局部 derivative，结果会错误。版本计数、functionalization 或显式 copy 用于保护语义。更一般地，aliasing 使两个变量名指向同一 storage，图的 value identity 与内存 identity 必须分开。

## 十三、执行成本
纯 DAG forward 每个 node 执行一次，理论工作量是局部 costs 之和；critical path 由最长依赖链决定，可并行度由同时 ready 的节点决定。两个图即使 FLOPs 相同，也可能因 fusion、memory traffic 和 parallel width 得到不同 latency。

## 十五、常见错误
1. 把 architecture diagram 当完整计算图；
2. 忽略 reshape/broadcast/reduction；
3. 把共享参数复制成独立参数；
4. 任意执行未就绪节点；
5. 原地覆盖 backward 所需值；
6. 忘记 train/eval 和 RNG；
7. 看到框架 gradient 就认为数学可微；
8. 用 node count 直接预测 runtime。

## 十六、回顾与练习
> [!summary]
> 计算图 = DAG + typed values + local operations + execution/state contract；拓扑序保证父值先就绪；tape/cache 记录实际 forward，为 reverse 提供证据。

# 激活函数的数值稳定、尺度与经验选择

> [!abstract] 本章主问题
> 激活函数比较必须同时通过数学等价、浮点稳定、深层尺度、系统成本和统计实验五道门。单次 accuracy、漂亮曲线或博客直觉都不足以决定选择；真正可复用的产物是带边界的证据协议。

## 课程位置与两遍学习路线

- **承接什么：** NN-17—23 已得到多种函数、局部导数、门控结构和 max-affine 选择，但这些局部事实尚未构成模型选择证据；
- **本页解决什么：** 把数学、浮点、传播、系统和统计五层压成一份可执行实验协议，并规定来源等级与结论边界；
- **后续为何需要：** 30.4 的初始化与信号传播将直接使用这里的 moment/gradient ledger，而不是重复做激活曲线比较。

**第一遍只做合法性筛选。** 先检查输出语义、stable primitive、极端输入和一阶/二阶 reference；数学或数值不合法的候选不进入昂贵训练。

**第二遍再做公平实验。** 同时执行 plug-in、retuned、matched-parameter、matched-FLOP/latency 与 matched-quality 轨道，并报告多 seed 不确定性和失败运行。

### 问题链

1. 三点 probe 能验证哪些局部事实，不能回答哪些深层或统计问题？
2. 数学等价的公式为什么可能在 FP16/BF16 下表现不同？
3. GLU/Maxout 与普通 activation 比较时怎样匹配参数、FLOPs 和 hidden width？
4. 多个候选中挑最高 validation score 会产生什么选择偏差？
5. 苏剑林博客、原论文、教材和官方实现分别能支持哪一级结论？

> [!check] 第一遍停靠线
> 若你能把 $s_\triangle$ 的局部 ledger 转成 stable forward/grad/gradgrad 测试，并为 GLU/Maxout 写出至少三条 matched-budget 轨道，就完成 30.3 第一遍；正式训练与统计结论留到第二遍。

## 符号与对象账本

| 对象 | 证据层 | 在 AI 决策中的作用 | 不可越级到 |
|---|---|---|---|
| probe ledger | 数学/单元测试 | 检查函数、导数与 convention | 整模型排名 |
| moment ledger | 深层传播 | 均值、方差、derivative second moment | population risk |
| budget ledger | 系统 | parameters/FLOPs/bytes/latency | 统计显著性 |
| seed distribution | 统计 | 均值、区间、失败率 | 跨任务因果定律 |
| source tier | 认识论 | 限定 claim strength | 用博客替代原始证据 |

### 贯穿算例：把三点结果升级为五道门

沿用 $s_\triangle=(-2,0,2)$。它已暴露 sigmoid/tanh 饱和、ReLU/Leaky kink、ELU 指数负支、GELU/SiLU 负 slope、GLU/SwiGLU 两路 VJP 和 Maxout winner routing。现在必须依次问：

1. **数学门**：定义、极限、导数和 kink/tie convention 是否一致；
2. **浮点门**：极端输入、stable formula、exact/approx 和 dtype 是否通过；
3. **传播门**：真实 $Z$ 分布下 moments、active/gate/winner statistics 是否稳定；
4. **系统门**：matched parameters/FLOPs/bytes 后 latency、fusion 与 energy 如何；
5. **统计门**：多 seed、预注册选择和独立 test 是否支持有限范围 claim。

三点 probe 只通过第一门的一部分；它不因数值精确就自动升级为“某激活更好”。

## 核心公式七问：$\text{claim}=\text{object}+\text{intervention}+\text{budget}+\text{uncertainty}+\text{boundary}$

| 问题 | 本式的回答 |
|---|---|
| 目的 | 把激活选择结论写成可复现、可证伪且不越界的证据对象 |
| 对象 | 候选实现、替换操作、资源约束、随机性与适用范围 |
| 来路 | 数学/数值/系统/统计证据不可互相替代的分层原则 |
| 步骤 | 先固定 object，再预注册 intervention/budget，最后报告 uncertainty 与 boundary |
| 读法 | “更好”只在指定模型、训练、硬件、预算和指标范围内成立 |
| 检查 | 若缺 seed、失败率、真实参数/FLOPs 或 implementation flag，claim 尚不可复现 |
| 去路 | 初始化消融、normalization/residual 联合实验、architecture search 与发布级 model card |

## 一、稳定公式清单

| 对象 | 不可靠路线 | 稳定路线 |
|---|---|---|
| sigmoid | $1/(1+e^{-x})$ 全域硬算 | 按符号分支或库 primitive |
| softplus | $\log(1+e^x)$ | $\max(x,0)+\log1p(e^{-|x|})$ |
| log-sigmoid | 先 sigmoid 再 log | $-\operatorname{softplus}(-x)$ |
| ELU | $e^x-1$ near 0 | `expm1(x)` |
| GELU | 不声明 exact/approx | 明确 erf/tanh/sigmoid 版本 |
| maxout | tie 时假装唯一导数 | 文档化 winner/tie convention |

数学等价只说明 real arithmetic；finite precision 还需 overflow、underflow、cancellation、rounding 与 branch audit。

## 二、尺度台账

对每层至少记录

$$
E[H],\quad E[H^2],\quad\operatorname{Var}(H),\quad
E[\phi'(Z)^2],\quad\|\bar H\|.
$$

前三者不可混用；导数二阶矩还需与 weight variance 结合。normalization 会重置部分统计量，residual 会相加相关分支，gating 会相乘两条相关支路。

## 三、五条比较轨道

1. **plug-in**：全部超参数固定，测替换鲁棒性；
2. **retuned**：每个激活独立调 learning rate/initialization；
3. **matched parameters**：尤其处理 gated/maxout hidden width；
4. **matched FLOPs/latency**：以真实 kernel 测量；
5. **matched quality**：达到同一 validation 阈值比较时间/能耗。

五条轨道回答不同问题，不能只展示对自己有利的一条。

## 四、统计与选择偏差

预注册主指标、训练预算、seed 数与 early-stopping rule。报告所有 failed/NaN runs、均值与不确定区间；若从许多 activations 中挑最优，validation selection 已产生 multiple-comparison optimism，最终 test 只能在选择完成后使用。

## 五、Kernel 与编译器现实

activation FLOPs 常不是瓶颈，但会影响 fusion、memory traffic、checkpoint residual、quantization 和 compiler lowering。GELU exact/approx、SwiGLU 三矩阵、Maxout candidate tensor 的成本必须以目标硬件实测；理论 operation count 不等于 latency。

## 六、来源证据分层

- 恒等式/证明：支持定义、导数、界与反例；
- 原始论文：支持明确 architecture/dataset/protocol 的经验；
- 官方实现文档：支持当前 API 与 kernel 语义；
- 科学空间/博客：提供推导视角与研究假说，需回查原论文；
- leaderboard/anecdote：只能作为待验证线索。

例如科学空间关于光滑近似、初始化和激活恒等式的文章适合生成问题与推导，但不自动升级为跨任务因果结论。

## 七、发布级验收矩阵

对每个候选检查：定义与极限、forward/grad/gradgrad reference、kink/tie、极端输入、dtype、shape/layout、fusion、determinism、moments、gradient、参数/FLOP/bytes、wall-clock、energy、train/validation/test、seeds 与 claim boundary。

### 从“想试一下”到可执行的预注册卡

比较开始前，至少冻结下表；结果出现后再改主指标或剔除失败 seed，就会把探索冒充成验证。

| 字段 | 最小可复现写法 | 要阻止的越级 |
|---|---|---|
| object | model commit、dataset split、dtype、compiler/kernel | 把函数名当成完整实现 |
| intervention | 只换 activation，或连 initialization 一起 retune | 混淆 plug-in 与 retuned 结论 |
| budget | steps/tokens、parameters、FLOPs、wall-clock 中哪个 matched | 用更大模型的收益归因于门控 |
| primary metric | 唯一主指标、越高/越低越好、最小有意义差异 | 事后挑最漂亮指标 |
| uncertainty | seed 列表、区间方法、NaN/OOM 处理 | 只报最佳 run |
| boundary | 任务、规模、硬件与调参范围 | 声称普遍最优 |

### 用小规模漏斗控制试验成本

1. **unit stage**：在 float64 高精度 reference 与目标 dtype 上比较 forward、gradient 和 gradgrad；
2. **layer stage**：用固定分布输入测量输出 moments、导数二阶矩、gate/winner 统计；
3. **short-run stage**：小模型多 seed 筛查发散、速度和对超参数的灵敏度；
4. **full-run stage**：只给通过前三层的候选分配完整预算，并保留所有失败记录；
5. **replication stage**：至少换一个规模或任务，只检查原 claim 在新边界内是否仍成立。

这个漏斗不保证找到全局最好 activation；它的价值是让显而易见的数学、数值和工程失败在昂贵训练前暴露。

> [!example] 一条边界清楚的结论
> “在固定模型、数据划分和 GPU 上，在 matched-parameter 且分别 retune 的预定范围内，SwiGLU 的五个 seeds 对主 validation 指标有某区间改善，但 latency 更高；尚未在其他规模验证。”
>
> 这种句子看似比“SwiGLU 更好”保守，实际上更有科学信息：它说明了对象、干预、预算、不确定性和尚未越过的边界。

## 九、决策规则与回顾

先用任务/输出支持排除不合法函数，再用数学与数值门排除不可靠实现；在 architecture-aware initialization 下做 matched-budget screening，最后小范围 retune。若差异落在 seed variance 与测量噪声内，优先选择更简单、稳定、已有融合支持的方案。

> [!summary]
> 激活选择不是函数名竞赛，而是数学—浮点—传播—系统—统计的联合审计。最可信的结论通常更窄，却更可迁移。

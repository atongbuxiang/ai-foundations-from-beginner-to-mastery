# 状态空间的递推—卷积对偶与并行扫描

> [!abstract] 本节主问题
> 离散线性时不变 SSM 可逐步 recurrence，也可在零初态/固定初态条件下展开为一维 convolution；更一般的仿射 recurrence 还能编码为带结合律的 scan。三者描述相关 input-output map，却具有不同的训练、流式、工作量、并行 span 与 IO 合同。

## 一、从离散 LTI recurrence 出发

采用索引

$$
x_{k+1}=\bar Ax_k+\bar Bu_k,\qquad y_k=Cx_k+Du_k.
$$

为简洁先设 $x_0=0,D=0$。逐步展开：

$$
x_1=\bar Bu_0,
$$

$$
x_2=\bar A\bar Bu_0+\bar Bu_1,
$$

$$
x_k=\sum_{j=0}^{k-1}\bar A^{k-1-j}\bar Bu_j.
$$

因此

$$
y_k=\sum_{j=0}^{k-1}C\bar A^{k-1-j}\bar Bu_j.
$$

定义 impulse-response kernel

$$
K_n=C\bar A^n\bar B,\qquad n\ge0,
$$

则 $y_k=\sum_{j=0}^{k-1}K_{k-1-j}u_j$。具体是否写成 $y_k=(K*u)_k$ 取决于输出与状态的 index convention；实现前必须用 impulse test 对齐一格偏移。

## 二、非零初态是额外自由响应

一般情况

$$
x_k=\bar A^kx_0+\sum_{j=0}^{k-1}\bar A^{k-1-j}\bar Bu_j,
$$

$$
y_k=C\bar A^kx_0+\sum_{j=0}^{k-1}K_{k-1-j}u_j+Du_k.
$$

所以仅做 input convolution 会漏掉 $C\bar A^kx_0$。训练时常取零初态；流式承接上一个 chunk 时初态通常非零，需 state-passing 或显式加自由响应。

## 三、固定 convolution kernel 的条件

单一 $K_n=C\bar A^n\bar B$ 要求：

- transition 对 state 是线性的；
- $\bar A,\bar B,C$ 不随时间、输入或状态变化；
- boundary/initial-state 约定固定；
- 序列长度内参数共享；
- 不在 recurrence 中夹入任意非线性。

若 $\bar B_k,C_k,\Delta_k$ 依赖 $u_k$，仍可能是线性于 state 的 time-varying recurrence，却不能由一个预先固定的 convolution kernel 表示。这正是 selective SSM 的关键边界。

## 四、卷积接口为何适合整段训练

长度 $L$ 的 kernel 生成后，direct convolution 为 $O(L^2)$（标量/通道常数略去），FFT convolution 通常约 $O(L\log L)$，并可对所有位置并行。代价包括：

- 先生成 $K_0,ldots,K_{L-1}$；
- padding 到线性卷积所需长度，避免 circular aliasing；
- FFT 的复数/实数变换与临时内存；
- kernel 参数化的数值条件。

短序列、很小状态或 streaming 时，逐步 recurrence 可能更合适。渐近复杂度不直接等于 wall-clock。

## 五、生成函数和 transfer function

形式生成函数

$$
K(z)=\sum_{n=0}^{\infty}K_nz^n
=\sum_{n=0}^{\infty}C(z\bar A)^n\bar B.
$$

在级数收敛或形式幂级数意义下，Neumann series 给

$$
\boxed{K(z)=C(I-z\bar A)^{-1}\bar B.}
$$

这是有理函数；其 poles 与 $\bar A$ eigenstructure 相关。[[S-2024-Su-10180-有理生成函数SSM]]用这一视角连接线性 RNN、resolvent 和 transfer-function parameterization。

需要区分：

- 形式幂级数恒等；
- 解析函数的收敛域；
- 单位圆上的频率响应；
- 有限长度 DFT samples。

它们相关但不完全相同。

## 六、仿射更新的结合律

时间变化的线性仿射 recurrence

$$
x_t=A_tx_{t-1}+b_t
$$

可把每一步编码为 pair $p_t=(A_t,b_t)$。定义“后做 $p_2$”的组合

$$
\boxed{p_2\otimes p_1=(A_2A_1,A_2b_1+b_2).}
$$

验证结合律：

$$
p_3\otimes(p_2\otimes p_1)
=(A_3A_2A_1,A_3A_2b_1+A_3b_2+b_3),
$$

$$
(p_3\otimes p_2)\otimes p_1
=(A_3A_2A_1,A_3A_2b_1+A_3b_2+b_3).
$$

因此可用 parallel prefix scan 同时得到所有 prefix compositions。注意 $\otimes$ 一般不交换；parallel scan 只需 associativity，不需 commutativity。

## 七、work、span 与 IO 分开

Sequential recurrence 的 work $O(L)$、span $O(L)$。理想树形 scan 仍有 $O(L)$ work，但 span 可为 $O(\log L)$，代价是并行调度、中间结果、矩阵/向量操作和内存访问。

对于 diagonal $A_t$，pair composition 可逐元素，成本远低于稠密 $N\times N$ 矩阵乘法。说“scan 是线性的”必须同时声明 state structure；稠密矩阵 pair 的常数和 $N$ 阶数可能巨大。

实际 GPU 性能还取决于：

- 是否把 parameter projection、scan 与 output 融合；
- 中间 state 是否写回 HBM；
- backward 重算还是保存；
- chunk 大小、batch、dtype 与 sequence length；
- 非结合的浮点舍入导致不同树顺序的微小差异。

## 八、训练、prefill 与 streaming

| 接口 | 合适形式 | 关键资源 |
|---|---|---|
| 整段训练 | FFT convolution 或 parallel scan | activation、kernel/scan IO |
| prefix prefill | scan/块递推 | prefix throughput、final state |
| 单步 streaming | recurrence | state bytes、step latency |
| chunked long stream | state passing + chunk kernel | boundary state、overlap |

同一参数化可以提供多个执行接口，但数值等价需测试 initial state、padding 和 precision。

## 十、浮点下“结合”要加注记

实数代数中 pair composition 严格结合；浮点加法和乘法不严格结合。不同 scan tree 可能产生舍入差异，长乘积还可能 underflow/overflow。工程验收应比较：

- sequential reference 与 scan 的相对/绝对误差；
- 不同长度、dtype 和状态尺度；
- forward 与 backward；
- deterministic setting 下重复性；
- stable parameterization 或 rescaling。

这不否定 scan 算法，只说明数学等价和 bitwise equality 是不同要求。

## 十一、常见错误

1. 忽略 initial-state 自由响应；
2. 用 circular FFT convolution 冒充 linear causal convolution；
3. 参数随输入变化仍写固定 $K$；
4. 把 associativity 误写为 commutativity；
5. 混淆 work、parallel span 和 wall-clock；
6. 忽略 dense state matrix 的 $N$ 成本；
7. 要求不同 scan tree 在浮点下 bitwise 相同；
8. 用整段训练并行性推断自回归 token 可并行生成。

## 十二、掌握标准

> [!summary]
> - 离散 LTI recurrence 展开为 impulse-response convolution；
> - 非零初态产生额外自由响应；
> - input-dependent/time-varying 参数破坏单一固定卷积核；
> - 仿射更新 pair 在正确顺序下满足结合律；
> - recurrence、convolution、scan 分别适合不同执行接口。

能展开前三步并对齐索引（A/B）、推导卷积与生成函数（C）、构造 non-LTI/initial-state 反例（D），并对 scan 做 work/span/IO/precision 审计（E）。

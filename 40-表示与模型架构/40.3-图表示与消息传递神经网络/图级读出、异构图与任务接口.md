# 图级读出、异构图与任务接口

> [!abstract] 本节主问题
> 同一个 GNN encoder 可服务节点、边、链接和整图任务，但输出对象、对称性、decoder、split 与泄漏风险不同。Graph readout 必须对节点重排不变；异构图还要为节点/边类型、关系方向和参数共享建立明确合同。

## 导读：同一个图表示，最后究竟要回答谁的问题

消息传递网络给每个节点生成了一个向量，但“有了节点向量”并不等于任务已经定义完毕。节点分类要回答某一个节点，边分类要回答一条已经存在的关系，链接预测要判断一个候选 pair，而图分类则要把整组节点压成一个不依赖存储顺序的对象。若不先确定预测对象，后面的 readout、decoder 和数据切分很容易互相冲突。

图级读出是这一步的核心接口。它必须忘掉节点编号的偶然顺序，却又不能无意中忘掉任务需要的计数、规模或类型信息。sum、mean、max 看上去只是三个简单的池化，却对应三种不同的统计假设。进入异构图后，节点类型、关系类型、方向和 self-loop 又决定参数究竟共享到什么程度；这些不是“工程细节”，而是模型表达的组成部分。

本节会沿着“预测对象 → 不变读出 → 异构关系 → decoder → split 与防泄漏”的顺序展开。你将看到一个 encoder 如何复用，也会看到为什么复用并不意味着所有任务可以共用同一套数据合同。最终目标不是背下 R-GCN 或 Deep Sets 的名字，而是能为任何图任务画出清晰的输入、状态、出口和可见性边界。

## 课程位置与两遍学习路线

- **承接什么：** ARCH-17—20 建立了节点级等变的消息传递与聚合器；本页把节点状态接到边、链接和整图的任务出口。
- **本页解决什么：** 说明 readout 的置换不变性、sum/mean/max 的统计差异、异构关系参数化以及 transductive/inductive/temporal split 的泄漏合同。
- **后续为何需要：** ARCH-24 将用这些任务接口讨论表达力 benchmark；只有先明确预测对象与 split，实验分数才有可比意义。

**第一遍只画接口图。** 对每个任务标出输入节点/边、输出索引和重标号后的行为，再比较三种 readout 保留了什么统计量。

**第二遍再审计数据合同。** 检查 inverse relation、target-edge removal、时间截断、negative sampling、batch index 和 isolated node；一个看似很高的分数可能只是 encoder 偷看了答案结构。

### 问题链

1. 节点、边、链接和图级输出分别是等变还是不变？
2. sum、mean、max 对图大小和计数做了什么不同假设？
3. 异构关系为何需要独立参数或可解释的共享结构？
4. decoder 的对称性如何限制可表达的关系？
5. transductive 与 inductive split 究竟改变了哪些可见信息？

> [!check] 第一遍停靠线
> 若你能为四类任务写出输出索引，并解释为什么 graph readout 必须满足 $r(PH)=r(H)$，就可以进入异构关系和防泄漏审计。

## 符号与对象账本

| 对象 | 数学身份 | AI 中的身份 | 不要偷换成 |
|---|---|---|---|
| $H$ | 节点状态矩阵 | encoder 输出 | 已经完成任务的预测 |
| $P$ | 节点重排矩阵 | 改变存储编号的同一张图 | 新的图语义 |
| $r(H)$ | 集合上的不变函数 | graph readout | 顺序相关 flatten |
| $\tau(v)$ | 节点类型 | heterogeneous node schema | 节点标签的类别预测 |
| $r(i,j)$ | 关系类型 | typed directed edge | 无方向的相似度 |
| $d(\cdot)$ | 任务 decoder | pair/graph prediction head | encoder 内部传播 |
| split | 数据可见性划分 | 泛化实验合同 | 一个无关紧要的采样参数 |

### 贯穿算例 $\mathcal G_\square$：同一节点状态的三种图摘要

沿用路径 $1\!-!2\!-!3$ 及节点状态 $H=(1,2,4)^\mathsf T$。三种最小 readout 分别给出

$$
r_{\mathrm{sum}}(H)=7,\qquad
r_{\mathrm{mean}}(H)=\frac73,\qquad
r_{\mathrm{max}}(H)=4.
$$

重排节点为 $PH=(4,1,2)^\mathsf T$ 后，三个结果仍然是 $7,7/3,4$，因此它们都满足不变性；但如果再复制一个状态为 $4$ 的节点，sum 会增加，mean 只按新规模重新平均，max 完全不变。选择 readout 于是等价于选择任务希望保留的统计量，而不是在三行 API 中随意挑一个。

若把边 $1\to2$ 标为 `writes`、边 $3\to2$ 标为 `cites`，异构 encoder 还必须决定两类关系是否使用不同的 $W_r$。之后的链接 decoder 只能在声明的候选 pair 和可见图上打分；否则同一组节点向量可能因为泄漏的目标边而得到虚假的高分。

## 核心公式七问

1. **为什么 graph readout 要求 $r(PH)=r(H)$？** 节点编号是表示方式，不是图的语义；重排不应改变同一张图的预测。
2. **sum、mean、max 各保留什么？** 分别偏向总量、平均量和坐标极值；选择它们就是选择统计假设。
3. **$W_r$ 为什么带下标 $r$？** 同一对节点的消息若属于不同关系，可能需要不同的变换与归一化。
4. **inverse relation 有什么代价？** 它提供反向消息，却也可能在链接预测中重新暴露被删除的目标边。
5. **decoder 为什么不能省略？** encoder 产生上下文表示，decoder 才定义候选 pair 或图状态如何映射到任务输出。
6. **transductive 与 inductive 差异在哪里？** 前者可让测试节点结构进入传播，后者要求测试对象及其结构不参与训练图。
7. **batch index 负责什么？** 它把 disjoint union 中的节点分回各自图，防止 message passing 或 readout 跨图串线。

### 一个具体的链接泄漏检查

假设目标是判断候选边 $(1,3)$ 是否存在。若训练图中删掉了正向边 $1\to3$，却保留自动生成的 `relation_inv` 边 $3\to1$，那么 encoder 仍能从邻居集合看到同一事实。此时即使 decoder 只接收 $(h_1,h_3)$，测试结果也不能解释为“从剩余结构泛化”。完整合同应同时记录：目标边及其 inverse 是否删除、负例怎样采样、时间截断点在哪里，以及 candidate pair 是否允许 self-loop。

### 任务合同模板

在实际项目中，建议为每个图任务逐项填写：

- **对象：** 节点、已存在的边、候选链接或整图；
- **输入：** 节点/边特征、关系方向、时间窗口和可见结构；
- **输出：** 等变张量或不变图向量，以及 decoder 的对称性；
- **切分：** train/validation/test 的单位、随机种子和 OOD 轴；
- **防泄漏：** 目标边、inverse、未来边和 graph size shortcut 的处理。

这张合同表比单独报告一个 accuracy 更能说明结果究竟回答了哪个问题。

填写合同后，再把 encoder、readout、decoder 和 split 画成四个独立框。任何一条边从目标标签回到 encoder 的路径都应被标记；任何一个 readout 若依赖节点存储顺序，也应在等变/不变检查中失败。这样做能把“模型结构正确”与“实验协议可信”放在同一张可复核的图上。

> 读图任务论文时，先复述它的对象、可见结构和 split，再评价模型名称或分数。

## 一、先确定预测对象

给定节点状态 $H=[h_1;\ldots;h_n]$：

- 节点分类：$\hat y_i=c(h_i)$，输出随节点重排；
- 边分类：$\hat y_{ij}=d(h_i,h_j,e_{ij})$，对应已观测边；
- 链接预测：$s(i,j)=d(h_i,h_j,r)$，对候选 pair/relation 打分；
- 图预测：$\hat y_G=c(r(H))$，readout $r$ 对行置换不变。

任务名字相近不代表数据合同相同。Edge classification 可以使用该边属性；link prediction 若把目标边留在 encoder 中，模型直接看到了答案结构。

## 二、Graph readout 的三个典型选择

$$
r_{\text{sum}}=\sum_i h_i,\qquad
r_{\text{mean}}=\frac1n\sum_i h_i,\qquad
r_{\text{max},k}=\max_i h_{ik}.
$$

三种读出都对节点排列不变，但“不变”不等于“保留的信息相同”。sum 会把每个节点的贡献累加，因此天然携带规模和计数；mean 把这种总量除以 $n$，更像在比较平均组成；max 只保留每个坐标曾经达到的极值。选择 readout 其实是在选择任务希望看到哪一种统计摘要，不能把它当作无关紧要的最后一行代码。可学习 Deep Sets 形式

$$
r(H)=\rho\!\left(\sum_i\phi(h_i)\right)
$$

更灵活；仍需定义域、容量和数值条件。Hierarchical pooling 或 attention readout 必须证明/构造为不变，不能依节点存储顺序。

## 三、Size signal 是特征还是混杂

某些分子性质随原子数增长，sum 合理；某些任务希望比较平均组成，mean 更合适。若 benchmark label 与图大小偶然相关，sum/readout 可能形成 shortcut。应报告仅用 $n,|E|,$ degree histogram 的弱基线，并按 size stratification 检查性能。

## 四、异构图的对象合同

异构图可包含 node type $\tau(v)$ 与 relation type $r(i,j)$。一个关系感知更新可写

$$
h_i'=\sigma\!\left(W_0h_i+
\sum_{r\in\mathcal R}\sum_{j\in\mathcal N_i^r}
\frac1{c_{i,r}}W_rh_j\right).
$$

读这个更新时要同时固定三件事：$r$ 决定当前消息属于哪种关系，$W_r$ 决定该关系怎样变换特征，$c_{i,r}$ 决定同一关系的邻居怎样归一化。关系参数越多，模型越灵活，但统计估计和内存成本也越高；basis 或 block 分解不是“免费压缩”，而是在表达力与共享假设之间重新取舍。

[[S-2018-Schlichtkrull-RGCN]] 用 relation-specific $W_r$ 建模知识图谱。关系很多时参数量 $O(|\mathcal R|d^2)$，可用 basis/block decomposition 共享结构；这是容量—统计效率取舍，不是纯实现技巧。

## 五、方向、逆关系与 self-loop

事实 `(Paris, capital_of, France)` 有方向。常见做法添加 inverse relation `capital_of_inv`，让消息反向流动；再加 self-loop 保留自身。三类边应有独立或明确共享的参数。

链接预测时若删除正向目标边却保留其 inverse，仍然泄漏。对 temporal KG，还要避免训练 encoder 看见发生在 prediction time 之后的边。

## 六、Decoder 不是 encoder 的附属细节

对链接预测，常见 decoder 如

$$
s_r(i,j)=h_i^\top R_r h_j
$$

或 MLP/translation/bilinear 变体。某些 decoder 对交换 $i,j$ 对称，无法表示反对称关系；某些关系矩阵参数量很大。Encoder 表达结构上下文，decoder 定义候选 pair 如何相互作用，二者必须共同审计。

## 七、Transductive 与 inductive split

- **Transductive node split**：训练时整图结构常可见，只隐藏部分标签；测试节点的信息可在 message passing 中参与；
- **Inductive node split**：测试节点及其相关边不进入训练图；
- **Inductive graph split**：测试是未见整图；
- **Temporal split**：严格按时间截断结构与标签；
- **Link split**：目标边从 encoder graph 移除，并设计 negatives。

随机节点 split 上的高分不能直接归于“泛化到新图”。图依赖也使 i.i.d. 样本直觉失效，需记录 split unit。

## 八、Batching 与空图/孤立点

多张图可做 disjoint union，并用 batch index 指定每个节点所属图；message passing 不跨图，readout 按 batch 分组。实现必须覆盖空邻域、单节点图、不同大小图和 isolated node。若 normalization 对 degree 0 未定义，应在加 self-loop 或显式 convention 后处理。

## 十一、常见错误

1. 把 edge classification 与 link prediction 混用；
2. 图分类使用顺序相关 flatten；
3. 忽略 sum/mean 对图大小的不同偏置；
4. 删除目标边却保留 inverse；
5. 用 transductive split 声称 unseen-graph generalization；
6. decoder 对称性与关系语义冲突；
7. batching 时错误跨图连边或跨图 readout。

## 十二、掌握标准

> [!summary]
> - 节点/边/链接/图任务具有不同输出与可见性合同；
> - graph readout 必须不变，并审计 size shortcut；
> - 异构图需要 type/relation/direction/self-loop 参数化；
> - split 与 target-edge removal 是模型定义的一部分。

能为四类任务写形状与对称性（A/B）、证明 readout 不变（C）、发现 inverse-edge leakage（D），并设计 inductive/temporal benchmark（E）。

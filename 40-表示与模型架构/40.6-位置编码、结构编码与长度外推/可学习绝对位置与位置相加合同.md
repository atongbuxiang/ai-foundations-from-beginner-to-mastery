# 可学习绝对位置与位置相加合同

> [!abstract] 本节主问题
> Learned absolute position embedding 是一张按 position ID 查表的参数矩阵。真正的模型合同不只是 $X=E+P$：还包括 position IDs 怎样生成、padding/packing 是否 reset、decode offset 如何延续、两个加数的尺度怎样匹配，以及超过训练表长时如何定义。

## 一、基本对象与 Shape

设 token embedding

$$
E_{tok}\in\mathbb R^{V\times d},
$$

最大位置数 $L_{\max}$ 的位置表

$$
E_{pos}\in\mathbb R^{L_{\max}\times d}.
$$

对 token IDs $x\in\{0,\dots,V-1\}^{B\times T}$ 与 position IDs

$$
r\in\{0,\dots,L_{\max}-1\}^{B\times T},
$$

lookup 后

$$
X_{tok}=E_{tok}[x]\in\mathbb R^{B\times T\times d},
$$

$$
X_{pos}=E_{pos}[r]\in\mathbb R^{B\times T\times d}.
$$

最常见输入为

$$
X_0=X_{tok}+\alpha X_{pos}+X_{type}.
$$

相加要求 batch、token 轴和 feature width 完全相容；若 position 为 $(T,d)$，broadcast 到 batch 必须是有意的。

## 二、为什么通常用相加而不是拼接

拼接会得到 $(B,T,d+d_p)$，下一层必须改变 projection shapes；相加保持 residual width $d$ 不变，并让任意线性投影同时读取 token 与 position：

$$
(e_i+p_i)W=e_iW+p_iW.
$$

但相加也意味着两种信息进入同一通道子空间，不能从 $e_i+p_i$ 唯一恢复 $e_i,p_i$。网络必须依数据和参数学会如何分离/组合。

相加不是“不会干扰 token”。若 $\|p_i\|\gg\|e_i\|$，位置可能主导；若 $\|p_i\|\ll\|e_i\|$，早期位置梯度/影响可能很弱。

## 三、尺度、初始化与 Input Norm

需登记：

- token 与 position 的初始化方差；
- 是否把 token embedding 乘 $\sqrt d$；
- $\alpha$ 固定、可学习还是隐含为 1；
- 相加后是否 LayerNorm/RMSNorm；
- dropout 在相加前还是后；
- embedding 与 output head 是否 tying。

若相加后立即 LayerNorm，整体共同缩放会被部分消去，但 token/position 的**相对方向与相对尺度**仍影响结果；不能说 LayerNorm 让初始化无关。

## 四、Position ID 不是永远的 0 到 T−1

### Right Padding

有效 tokens 常用 $0,\dots,n-1$；padding IDs 可以固定为 0 或继续递增，只要 padding rows/columns 在后续严格屏蔽。但若 padding state进入 pooling或作为 keys，选择会泄漏长度。

### Left Padding

若生成时使用 left padding，position IDs 通常需让真实 token 从 0 开始，而不是直接等于 padded array index；否则相同文本因 batch padding 不同得到不同位置。

### Packed Sequences

把多个样本拼在同一 row 时需同时决定：

- attention 是否 block-isolated；
- 每个样本 position 是否 reset；
- 跨 segment 是否允许相对距离；
- loss mask 与 position reset 是否一致。

只 reset positions 而未隔离 attention 仍会跨样本泄漏。

## 五、增量解码的 Offset

已有缓存长度 $t$ 时，新 token position 通常是 $t$，而不是每步重新用 0。若有 prompt padding、prefix tuning、sliding window 或被丢弃 cache，则需区分：

- absolute sequence position；
- cache storage index；
- visible window 内局部 index。

三者不一定相同。Full forward 与 cached decode 等价测试必须比较同一 absolute position IDs。

## 六、可学习表怎样学习

位置表的第 $i$ 行只在训练样本实际使用 position $i$ 时收到直接梯度：

$$
\frac{\partial\mathcal L}{\partial E_{pos}[i]}
=\sum_{b,t:r_{bt}=i}
\frac{\partial\mathcal L}{\partial X_{0,bt}}.
$$

因此训练长度分布很重要：高位置出现少，其估计噪声与更新次数不同。表是共享参数，但不具有函数式平滑约束；相邻 rows 可以学得相近，也可以完全不同。

## 七、最大长度之外没有“自然外推”

若测试需要 $r\ge L_{\max}$，原表没有对应 row。常见方案：

1. **报错/截断**：保持已训练合同，不宣称更长；
2. **随机扩表**：新 rows 未训练；
3. **复制/周期重复**：产生位置碰撞；
4. **一维插值**：把离散 rows 当作连续曲线；
5. **改用函数式或相对位置**；
6. **扩表后长序列微调**。

一维插值改变邻近差向量和位置谱。即使插值值落在旧 rows 的凸包，也不表示 Transformer 在这些中间坐标上受过训练。

## 八、ViT 的二维位置表

ViT 常将 $H_pW_p$ 个 patch positions flatten，再加 class position。分辨率从 $H_p\times W_p$ 变为 $H_p'\times W_p'$ 时，正确的基本流程是：

1. 分离 class/special positions；
2. 把 patch rows reshape 回二维网格；
3. 在 row/column 平面插值；
4. flatten 回新顺序；
5. 拼回 special position。

直接对一维 flattened table 插值会把 row boundary 当作普通相邻点，可能破坏二维邻接。

## 九、BERT 与 ViT 的证据怎样读

[[S-2019-Devlin-BERT]] 和 [[S-2021-Dosovitskiy-ViT]] 展示 learned absolute positions 在各自训练协议中可工作，属于 E。

它们不证明：

- learned absolute 总优于 fixed/relative；
- 表内每个位置都同样学好；
- 训练长度外可直接使用；
- 插值无损；
- position vector 是模型顺序信息的唯一来源。

## 十、实现不变量

至少测试：

1. 相同有效文本在不同 right/left padding 下 logits 一致；
2. packed 样本互不读取；
3. full forward 与 cached decode position offset一致；
4. 越界 position 明确报错或进入已声明扩展方案；
5. resize 前后 special token没有混入 patch grid；
6. position table 的最大/最小更新频次被监测；
7. 不同 dtype 下 lookup/add 不产生未预期 cast。

## 十二、常见错误与掌握标准

常见错误：把 position table 参数量写成 $Td$ 而忘记实际最大表长；position 与 token shape相同就认为尺度相同；left padding 用数组下标；cache 每步 position reset为0；packing只 reset位置不隔离 attention；ViT直接一维插值含CLS的整张表；把“能扩表”写成“能外推”。

> [!summary]
> Learned absolute position 是 $L_{\max}\times d$ 的离散参数表。相加保持 residual width，却要求 shape、尺度和 ID 语义一致；padding、packing、cache offset 与二维 resize 都是合同的一部分；表外位置没有天然定义。

能手算 lookup/add shapes（A/B）、推导位置表梯度与 offset（C）、构造 padding/插值反例（D），并审计真实训练—服务 position pipeline（E）。

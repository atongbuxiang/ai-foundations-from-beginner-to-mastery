# 位置分辨率、混叠与长度外推评测

> [!abstract] 本节主问题
> “Context window = 128K”可能只表示接口能接收 128K tokens。有效上下文不是一个无条件数字，而是一条由任务、证据位置、依赖跨度、干扰、质量阈值、tokenizer与系统预算共同定义的性能曲线。

## 一、位置分辨率怎样量化

对位置特征 $p(n)$，局部一阶敏感度可看

$$
\left\|\frac{\partial p(n)}{\partial n}\right\|.
$$

对一组 sin/cos频率，

$$
\left\|\frac{\partial p(n)}{\partial n}\right\|^2
=\sum_i\omega_i^2.
$$

它与 $n$ 无关，但只表示原始 position vector对连续坐标的局部变化，不表示投影后或网络中的可辨识性。

更直接的 pair metric：

$$
D(\Delta)^2
=\|p(n+\Delta)-p(n)\|^2
=2\sum_i[1-\cos(\omega_i\Delta)].
$$

若 $D(1)$ 很小，邻位拥挤；若某个大 $\Delta$ 的 $D(\Delta)$ 很小，出现近似 alias。

## 二、PI 怎样压缩分辨率

Position Interpolation $n\mapsto n/k$ 后

$$
D_{PI}(\Delta)^2
=2\sum_i
\left[1-\cos\left(\frac{\omega_i\Delta}{k}\right)\right].
$$

对小 $\Delta$ 用 $1-\cos x\approx x^2/2$：

$$
D_{PI}(\Delta)^2
\approx\frac{\Delta^2}{k^2}\sum_i\omega_i^2.
$$

局部距离约缩小 $1/k$。这是 I/近似 T（需小角条件）；它解释为何扩展倍数越大，邻位相位越拥挤，并不单独预测任务损失。

## 三、有限精度混叠

即使实数位置特征不同，存成 BF16/FP16 后可能相同或投影差低于噪声。风险来自：

- $n\omega_i$ 大时 angle reduction；
- 低频邻位差小；
- PI 进一步缩小差；
- sin/cos cache在低精度预计算；
- Q/K projection丢弃相关方向；
- softmax temperature和content logits掩盖微小位置差。

测试应比较 FP64/FP32 reference与目标dtype，扫描 position、frequency、pairing和相位误差，而非只检查无 NaN。

## 四、Context 能力的四级阶梯

### 1. Accepts Input

Tokenizer、API、kernel和memory能接收长度 $T$。

### 2. Numerically Stable

Logits、norm、softmax、cache无 NaN/overflow，full-vs-cache在容差内。

### 3. Retrieves/Tracks

能找到给定事实、复制字符串、追踪状态或聚合多个证据。

### 4. Reasons/Improves

增加相关 context真正提高预测/推理，并能忽略干扰；输出忠实、校准且成本可接受。

前一级是后一级的必要条件之一，不是充分条件。

## 五、PPL 为什么会给“虚假的成功感”

语言的下一个 token大多依赖局部上下文。即使模型完全忽略很远内容，平均 PPL仍可能不错。更长 context还可能通过增加局部相邻 tokens改善 loss，却未证明远程依赖。

[[S-2023-Su-9948-长度外推技术复盘]] 推荐一种更公平比较：不同 context lengths读取不同长前缀，但只在相同末端 target window上计 loss。

若最长输入 $C$、固定评分区间 $\mathcal T$，报告

$$
\operatorname{NLL}(C)
=-\frac1{|\mathcal T|}
\sum_{t\in\mathcal T}
\log p(x_t\mid x_{t-C:t-1}).
$$

目标 tokens一致，$C$ 的边际作用才较可比。仍需构造确实依赖远处信息的 subset。

## 六、Needle Retrieval 的完整矩阵

单个 needle 放在固定末尾太容易。至少扫描：

- context length；
- needle位置：start/middle/end；
- needle数量；
- distractor相似度；
- key/value长度与格式；
- exact match/paraphrase；
- query在前还是后；
- prompt模板；
- generation/stop规则；
- 多 seed。

[[S-2024-Liu-Lost-in-the-Middle]] 展示 relevant evidence position可产生非单调性能；所以平均一个位置会掩盖中部失败。

## 七、从检索到推理

长上下文任务可分：

1. 单事实检索；
2. 多 needle聚合/计数；
3. multi-hop tracing；
4. 顺序/状态机；
5. 跨文档矛盾消解；
6. 长摘要与覆盖；
7. code repository依赖；
8. 长程生成一致性。

一个模型可通过 substring matching做1，却在3–8失败。Advertised context不能由单一 passkey定义。

## 八、RULER 与 LongBench 的互补

[[S-2024-Hsieh-RULER]] 用可控 synthetic tasks随长度扫描 retrieval、multi-hop、aggregation等，适合隔离变量并定义 task-specific effective context。

[[S-2024-Bai-LongBench]] 覆盖中英多任务真实/半真实长文本，适合检查跨任务迁移。

互补边界：

- Synthetic易控制，但可能不代表真实文档；
- Real benchmarks更真实，但任务难度、污染、metric和长度不可完全控制；
- 两者都要报告tokenization后长度、截断、prompt和版本。

## 九、形式语言与非局部任务

[[S-2023-Su-9444-长度外推与位置鲁棒性]] 借 CHE 等形式任务提醒：语言模型指标有强局部性，ALiBi/窗口等局部先验在非局部规则任务上未必占优。

应加入训练短、测试长且规则长度无关的任务：

- parity/even pairs；
- copy/reverse；
- balanced parentheses；
- state tracking；
- sorting/bucket；
- first-last equality。

但形式任务成功也不等于自然语言推理；它验证的是算法外推的特定分量。

## 十、分辨率、距离与任务干预

仅画 $D(\Delta)$ 或 RoPE kernel不够。应把位置机制与任务连接：

1. 选定远程事实 $z$；
2. 保持其他文本不变，改变 $z$；
3. 测输出是否随 $z$正确改变；
4. 在不同 $\Delta$、位置和长度重复；
5. 与 local-window、NoPE、原 RoPE等对照；
6. 同时测 attention/logit/representation诊断。

只有输出干预响应能支持“模型利用该远程信息”；attention heatmap只是 O。

## 十一、长度曲线与有效上下文定义

对任务 $\tau$、阈值 $\eta$，可定义

$$
L_{\mathrm{eff}}(\tau,\eta)
=\max\{L:\operatorname{score}_\tau(L)\ge\eta\}.
$$

但 $L_{\mathrm{eff}}$ 还依：

- evidence position分布；
- distractor数量；
- decoding；
- prompt；
- hardware budget；
- latency/memory threshold。

因此更好的报告是 score-vs-length曲线及置信区间，而不是单一最大值。

## 十二、系统账不能缺席

Dense attention prefill pair数为 $O(T^2)$，KV cache为 $O(T)$。即使质量保持：

- prefill latency可能不可接受；
- cache超显存；
- tensor parallel通信增长；
- RoPE scaling/recompute不兼容cache；
- 长输出decode读取带宽巨大。

可接受长度与可部署长度不同。报告 tokens/s、首token、逐token、cache bytes、batch和硬件。

## 十三、完整 Evaluation Card

| 字段 | 必须记录 |
|---|---|
| Claim | 接受、稳定、检索、推理、生成、效率中的哪一项 |
| Base model | checkpoint、position scheme、训练长度 |
| Extension | 公式、scale/base、微调token/FLOPs与数据 |
| Length | tokenizer后分布，不只字符/词 |
| Position | start/middle/end/均匀及绝对/相对 |
| Dependency | 所需跨度、hop数、needle数 |
| Controls | distractors、prompt、decoding、seed |
| Metrics | fixed-target PPL、accuracy、faithfulness、CI |
| Short regression | 原训练范围质量 |
| System | kernel、dtype、cache、latency、memory、hardware |
| Boundary | 未测规模、语言、任务和长度 |

## 十五、常见错误与掌握标准

常见错误：最大可输入长度当有效长度；只报末尾 needle；PPL改善当远程推理；不同context比较不同target tokens；忽略短范围 regression；只报平均不报长度/位置；synthetic成功等于真实文档；无NaN等于数值正确；不报tokenizer、cache和硬件；用单个seed选择最佳scale。

> [!summary]
> 位置分辨率可用多频距离与有限精度误差诊断，但网络利用仍需任务干预。长上下文能力至少分接受、稳定、检索、推理四级；PPL、needle、RULER、LongBench和系统指标各有盲区。有效上下文应报告任务特定的长度曲线，而非无条件单值。

# 数据优化器调度交互、混杂与归因边界

> [!abstract] 本节目标
> 把“改了配置，指标变好”改写成明确的因果问题。你将能定义 treatment、outcome 与 experimental unit，画出数据—优化器—调度—系统 DAG，识别 confounder、mediator、collider 和 post-selection，并为无法随机化的比较写出诚实边界。

## 一、先问：我们想估计哪个反事实差异

设 $A\in\{0,1\}$ 表示是否采用某个训练改动，$Y(a)$ 表示同一实验单位在干预 $A=a$ 下的潜在结果。平均处理效应写成

$$
\operatorname{ATE}=\mathbb E[Y(1)-Y(0)].
\tag{1}
$$

这行公式逼迫我们回答四个问题：

1. $A$ 到底是 Adam→Muon，还是连同 LR/schedule/WD 一起改变的 recipe？
2. $Y$ 是固定 token 后 validation loss、固定质量所需时间，还是选择后 test score？
3. experimental unit 是 seed、数据抽样、预训练 checkpoint、任务还是完整集群运行？
4. 期望对哪个分布取：当前数据/硬件，还是目标部署环境？

不回答这些问题，“方法提升 0.3”没有稳定含义。

## 二、Training treatment 通常是一个 bundle

实际切换 optimizer 往往连带：

$$
A=(\text{direction},\eta(t),\lambda(t),\text{warmup},
\text{clip},\epsilon,\text{batch},\text{precision},\text{kernel}).
\tag{2}
$$

若所有分量一起变，能识别的是**recipe bundle effect**，不能把增益单独归给 optimizer direction。要分解机制，需后续 factorial/mediation 设计。

同样，“新数据”可能伴随 tokenizer、dedup、length distribution、packing、curriculum 和训练时长改变；“系统优化”可能改变 reduction order、precision 与有效 batch。配置 diff 应是语义 diff，不只是两份 YAML 的文本差异。

## 三、一个训练因果图

考虑以下变量：

- $D$：data mix/quality/length；
- $O$：optimizer；$S$：schedule；$P$：precision/system；
- $M$：gradient/update/activation 中介；
- $C$：compute budget 与 early stopping；
- $V$：validation metric；$Y$：最终 test/deployment outcome；
- $U$：未记录的 run difficulty、时间/硬件漂移。

典型箭头有

$$
(D,O,S,P)\to M\to V\to Y,
\quad
(D,P)\to C\to V,
\quad
U\to(A,Y).
\tag{3}
$$

若新 optimizer 总是在更新后的集群、更新后的数据上运行，calendar time $U$ 同时影响 treatment 与 outcome，形成 confounding。[[S-2015-Sculley-Hidden-Technical-Debt]] 提醒 pipeline、缓存、消费者和反馈回路都可能是图中的隐藏节点。

## 四、四类变量不要乱控制

### 4.1 Confounder

$Z\to A$ 且 $Z\to Y$。若观测比较满足可交换性，需条件化/匹配/加权；更好的是设计阶段随机化。

### 4.2 Mediator

$A\to M\to Y$，例如 optimizer 改变 update spectrum，再改变 loss。估计总效应时随意控制 $M$ 会截断真实路径；研究机制时才定义 direct/indirect effect，并承担更强假设。

### 4.3 Collider

$A\to C\leftarrow U$。例如只分析“成功跑完的 runs”，而成功同时受方法和机器/seed 难度影响，条件化 success 会打开伪关联。

### 4.4 Post-treatment selection

用同一 validation set 选择 checkpoint/hyperparameter 后，再把所选 validation score 当无偏 outcome，是处理后的选择偏差。最终 test 必须保持独立，或明确目标就是“完整 selection procedure 的表现”。

## 五、交互效应意味着“主效应”依赖上下文

设 optimizer $O\in\{-1,+1\}$、schedule $S\in\{-1,+1\}$，响应模型

$$
Y=\beta_0+\beta_OO+\beta_SS+\beta_{OS}OS+\varepsilon.
\tag{4}
$$

optimizer 在 $S=s$ 下的效应是

$$
Y(+1,s)-Y(-1,s)=2\beta_O+2s\beta_{OS}.
\tag{5}
$$

若 $\beta_{OS}$ 大，“optimizer 的效果”随 schedule 改变，单一主效应并不完整。数据 mix、batch、precision 与 optimizer 也常有类似交互；这正是下一节 factorial design 的动机。

## 六、Simpson 悖论：总体改善可能来自任务组成

假设旧方法在短序列和长序列的成功率分别为 90%、60%，新方法分别为 92%、65%，在两组内都更好。但旧 run 80% 是短序列，新 run 20% 是短序列：

$$
Y_{old}=0.8(0.90)+0.2(0.60)=0.84,
$$

$$
Y_{new}=0.2(0.92)+0.8(0.65)=0.704.
\tag{6}
$$

总体看新方法更差，分层看却更好。反向翻转同样可能。解决方式不是总要“控制更多”，而是先确认 sequence length 是 baseline confounder、mediator 还是 treatment 的一部分，再定义目标总体的标准化权重。

## 七、训练中最常见的八个混杂源

| 混杂源 | 典型伪结论 | 设计补救 |
|---|---|---|
| calendar/code drift | 新方法因后来运行而更好 | 交错随机运行、commit/env hash |
| data order/mix | optimizer 改善其实来自更容易 batch | paired seed/data cursor、分层 |
| tuning budget | 新方法获更多 trial | 匹配总预算与 search protocol |
| early stopping | 快起步方法更常被选中 | 固定 horizon/target 与 selection rule |
| failure deletion | 不稳定方法只留成功尾部 | intention-to-run、保留失败分母 |
| precision/kernel | 算法和数值路径一起变 | 精度/系统做独立 factor |
| checkpoint reuse | 对照从不同 pretrain state 出发 | 同一 checkpoint 配对/block |
| evaluation reuse | 调参过拟合 validation | 独立 final test/嵌套选择 |

[[S-2022-DAmour-Underspecification]] 进一步指出：即使开发指标相同，不同 seed/pipeline 仍可在部署相关行为上分歧；因此 outcome 必须覆盖真正关心的 stress axis。

## 八、最可靠的识别来自设计

若可控制训练，优先顺序是：

1. **随机化** treatment assignment，打断已知/未知 baseline confounder 与 $A$ 的系统联系；
2. **配对/阻断**：同一 data seed、checkpoint、hardware block 内比较，降低 nuisance variance；
3. **factorial**：同时改变多个 factor 以估计交互；
4. **replication**：对真正 experimental unit 独立重复；
5. **预注册**：先固定 estimand、outcome、failure、stopping 与 analysis。

随机化不保证样本很小时完全平衡，但使效应估计有设计基础。Blocking 后仍需在分析中保留 block/paired structure。

## 九、无法随机化时，结论必须降级

[[S-2025-Hernan-Robins-What-If]] 的观测识别至少要求：

- **consistency**：记录的 treatment 对应定义清晰的版本；
- **exchangeability**：给定测得协变量后，不再有共同原因；
- **positivity**：每类协变量都有两种配置的可能性；
- **measurement**：treatment、outcome、covariate 被可靠测量。

深度学习历史日志常违反这些条件：旧 GPU 从未跑新配置、失败 run 无日志、pipeline 版本未记录。此时可以报告 adjusted association、sensitivity analysis 或 case study，不应写成已识别的 causal effect。

## 十、时间先后、相关、中介与因果证据分层

可用五级语言控制结论：

| 证据 | 合理表述 | 不应升级为 |
|---|---|---|
| 同时变化 | “相关/伴随” | 原因 |
| 先后顺序 | “X 先于 Y” | 充分因果 |
| 机制中介吻合 | “与路径一致” | 排除替代解释 |
| 随机干预 + 配对重复 | “在该协议下估计效应” | 跨任务普适 |
| 跨环境复验/机制干预 | “在列明范围内稳健” | 无边界定理 |

这套语言也适用于 root-cause analysis：日志时间线提出候选，重放与干预才提高因果等级。

## 十一、科学空间案例：低精度 Attention 的“因还是果”

[[S-2025-Su-11371-低精度Attention舍入偏差]] 明确提出舍入偏差与 attention collapse 的因果方向问题。可设计：

1. 固定 checkpoint/batch/RNG，只随机或切换 rounding/accumulation；
2. 按时间记录 local rounding error $M_1$、attention concentration $M_2$、gradient/update $M_3$ 与 loss $Y$；
3. 加入 FP32 reference、非 attention 低精度对照和 concentration-matched 输入；
4. 检查 $A\to M_1\to M_2\to M_3\to Y$ 的时间和干预响应；
5. 报告未支持的替代路径。

仅“切 FP32 后不崩”识别的是一个较大的 precision bundle effect，不足以单独归因到特定 Attention 舍入偏差。

## 十三、核心结论

因果归因始于精确定义 treatment、outcome、experimental unit 和目标分布。训练 recipe 往往是 bundle，主效应依赖交互，失败删除和 checkpoint selection 会制造 collider/selection bias。能随机化就用设计识别；不能随机化时，把假设、positivity 缺口和结论等级如实写出。

# 实验 - 低精度数值、分布式语义与系统证据审计

> [!abstract] 实验结论
> Python 标准库实验用 10 条分账轨道和 38 项机器断言，验收 ulp/range、loss-scale 控制流、随机舍入矩、affine quantization、全局样本加权、ring bytes、并行 tensor shape、ZeRO 稳态与峰值、offload/Roofline 下界以及浮点非结合律与 E0—E5 证据门。38/38 断言通过；从另一空目录复跑时，1 JSON、10 CSV、3 SVG 共 14/14 个文件逐字节一致。它支持恒等式、手算 oracle 与反例，不是 GPU kernel benchmark，更不是真实分布式训练的 E3/E4 质量证据。

## 一、研究问题与预注册门

| ID | 轨道 | 可证伪预期 |
|---|---|---|
| H1 | dtype contract | BF16 与 FP32 exponent 位相同但 BF16 ulp 更粗；TF32 multiply 与 FP16 precision bits 相同却不是同一 storage contract |
| H2 | loss-scale clocks | 安全 scale 代理区间为 $[64,128]$；五次 attempt 只有四次成功 update；overflow 不推进 optimizer |
| H3 | stochastic rounding | $x=.1$ 在 $0,.25$ 间的 SR 条件期望为 $.1$，误差方差 $.015\le.015625$；固定微小更新五步期望到 $.9$ |
| H4 | quantization | 2-bit affine oracle 的 code 为 $0,1,2,3$；8-bit Adam-state 账由 16 降至 10 B/parameter；scale metadata 使 payload 压缩略小于 $4\times$ |
| H5 | global batch | unequal ranks 的 sample mean 为 $33/9$，equal-rank mean 为 $4$，两者必须被检测为不同 estimator |
| H6 | ring All-Reduce | $P=8,M=1$ GiB 时每 rank volume 为 $1.75$ GiB；两阶段共 $2(P-1)$ 轮 |
| H7 | model parallel | column TP 输出宽度为 $K/4$；row TP 需要 sum；$P=8,M=32$ 的简化 pipeline 效率为 $32/39$ |
| H8 | ZeRO/FSDP memory | DDP/ZeRO-1/2/3 稳态为 16/5.5/3.75/2 B/parameter；2 GB shard 不等于 15.4 GB live peak |
| H9 | offload/Roofline | ridge 为 100 FLOP/byte；$I=40$ 上界 120 TFLOP/s、$I=200$ 上界 300；24 GB/48 GB/s 的不可重叠传输下界为 .5 s |
| H10 | reproducibility evidence | 浮点两种结合顺序得到 3.14 与 0；E3 首次直接检验训练质量，E5 才支持有 control 的特定因果判断 |

## 三、关键数值摘要

| 轨道 | 关键观测 | 证据层级 |
|---|---:|---|
| dtype | 1 附近 ulp：FP32 $2^{-23}$、FP16/TF32 $2^{-10}$、BF16 $2^{-7}$、E4M3 $2^{-3}$ | exact field-level identity |
| loss scaling | scale-after 序列 1024, 2048, 1024, 1024, 2048；update 4/attempt 5 | deterministic state machine |
| SR | $p_{up}=.4$，$E[Q]=.1$，$Var=.015$ | exact two-point distribution |
| quantization | dequant 为 $-1,0,1,2$；state 理想节省 6 B/parameter；bucket 约 $3.94\times$ | affine oracle + byte ledger |
| global batch | sample-weighted $3.666667$；rank mean $4$ | exact estimator counterexample |
| ring | 8 ranks、1 GiB：每 rank 1.75 GiB | analytic payload model |
| parallelism | column local output $8\times2048$；pipeline efficiency $.820513$；expert capacity 640 | shape/schedule construction |
| ZeRO | 1B、8 ranks：ZeRO-3 steady 2 GB；示意 live peak 15.4 GB | lifecycle ledger |
| Roofline/offload | ridge 100；40→120、200→300 TFLOP/s；transfer .5 s > compute .35 s | upper/lower-bound proxy |
| reproducibility | left association 3.14、right association 0；64-way efficiency 69.44% | floating counterexample + evidence labels |

## 四、实验图 1：表示、控制流与 estimator 不能合称“低精度”

先看图回答：左栏为什么 BF16 range 接近 FP32 却仍有更粗 ulp？右栏 RN 与 SR 在相同微小更新下分别产生停滞和方差，哪一条结论只在条件期望层成立？

![[00-知识库管理/_assets/plots/training-optimization/plot-low-precision-state-estimators-audit-v1.svg|900]]

> [!figure] 图 EXP-TRN-608-01　Ulp、loss-scale 可行区与随机舍入期望
> 左栏从 fraction bits 精确生成 1 附近的格距，并单列 gradient range 给出的 scale 可行区；右栏比较固定 $-.02$ 微小更新下 RN storage 停滞与 SR ensemble expectation。来源：[[experiment_low_precision_distributed_audit_v1.py]] 确定性生成；SVG SHA-256 `194fc8c53bfee52efec2502c1279b2683abeb56031398aec5e8d929afaf0d61c`。

**怎样读图**：条长表达的是 $\log_2(ulp)$ 的教学映射，不是吞吐；黄色区间只说 gradient min/max 同时可表示。右栏绿线是解析期望，不是一条真实采样路径。

**图没有证明什么**：它没有模拟 subnormal、FTZ、动态 amax、kernel accumulation 或自适应 optimizer，也没有证明 SR 的非线性训练终点无偏。

> [!figure] 图 EXP-TRN-608-02　Unequal-rank estimator 与分片内存时间线
> 左栏保留每 rank 的 sample count 与 gradient sum，最后只除一次总 count；右栏比较 1B 参数、8 ranks 的理想稳态 bytes，并叠加示意 gather、activation、workspace 与 buffer。来源：同一标准库脚本；SVG SHA-256 `c0e1027a3ede30dccb9984f29a85c3f433bd4307e7ded520c9348faa004bc1b0`。

**图没有证明什么**：它不测 NCCL/FSDP schedule、allocator fragmentation、prefetch 或 topology，也不表示所有实现都采用同一 16 B/parameter 账。

## 六、实验图 3：性能上界必须接到质量与因果证据

先看图回答：$I=200$ 的点为什么不能超过 300 TFLOP/s？即使 E2 profiler 证实通信尾巴缩短，为什么仍不能替代 E3 matched learning curve？

![[00-知识库管理/_assets/plots/training-optimization/plot-roofline-reproducibility-audit-v1.svg|900]]

> [!figure] 图 EXP-TRN-608-03　Roofline、offload 下界与 E0—E5 证据阶梯
> 左栏由 $\min(C,BI)$ 生成三点上界，并计算不可重叠 offload 传输下界；右栏把 manifest、counter、critical path、quality、paired uncertainty 与 causal control 分级。来源：同一标准库脚本；SVG SHA-256 `61d016cdca30f28c3ffe664a3238ceba2cf42ee5ef62f44f7d13ec239c8f6475`。

**怎样读图**：Roofline 蓝线是可达率上界而非实测拟合；证据阶梯从下到上增加的是可回答问题，不是把一个 counter 重复包装六次。底部非结合例说明数值差异来源，却没有直接宣布决策失败。

**图没有证明什么**：代理没有覆盖 latency、overlap、contention 或真实 kernel efficiency；E5 也只能支持已声明任务、规模、干预与 control 下的局部因果结论。

> [!warning] 复现边界

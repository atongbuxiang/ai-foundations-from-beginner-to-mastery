# 训练系统的对象、状态与一步更新合同

> [!abstract] 一句话结论
> 一次训练不是“算梯度再减一下”这么简单，而是数据状态、模型参数与缓冲区、随机数、梯度、优化器状态、精度控制器和调度器共同发生的一次状态转移。只有把这些对象和执行顺序写全，“同一个优化器”“可复现”与“两个训练等价”才是可检验的说法。

## 一、先看一个会产生不同答案的最小问题

设标量参数 $\theta=1$，两个样本在当前参数处给出梯度 $g_1=2,g_2=4$，学习率 $\eta=0.1$。

- 对 batch **求平均**：$\widehat g=(2+4)/2=3$，所以 $\theta^+=1-0.1\times3=0.7$；
- 对 batch **求和**：$\widehat g=6$，仍用 $0.1$ 时得到 $\theta^+=0.4$；
- 先分别做两次 optimizer step：$1\to0.8\to0.4$；若损失非线性，第二个梯度还应在 $0.8$ 而不是 $1$ 处重算。

三段代码都可能被口头称为“batch size 2 的 SGD”，轨迹却不同。缺失的是一份**训练步合同**。

## 二、训练对象总账

以第 $t$ 个 optimizer step 的开始为边界，定义完整状态

$$
X_t=(\theta_t,b_t,s_t,r_t,d_t,c_t,q_t,\tau_t).
$$

| 符号 | 类型 | 含义 |
|---|---|---|
| $\theta_t$ | 参数张量族 | linear/attention/embedding 等可训练权重 |
| $b_t$ | 模型 buffer | BatchNorm running statistics、缓存等非梯度状态 |
| $s_t$ | 优化器状态 | momentum buffer、二阶矩、step counter |
| $r_t$ | RNG 状态族 | 数据、dropout、augmentation、设备随机流 |
| $d_t$ | 数据迭代器状态 | permutation、shard、cursor、sampler epoch |
| $c_t$ | 训练控制状态 | scheduler、warmup、early stopping、curriculum |
| $q_t$ | 数值状态 | dtype、loss scale、overflow flag、accumulator |
| $\tau_t$ | 计数与时钟 | micro-step、optimizer-step、seen samples/tokens |

这里的“状态”采用计算机科学中的严格含义：若不把它保存下来，仅凭当前 $\theta_t$ 不能唯一决定下一步。

> [!warning] 参数不是全部模型状态
> BatchNorm 的 running mean/variance 不在 optimizer parameter list 中，却会改变后续输出；dropout 没有持久 buffer，但它消耗 RNG 状态。只保存 `model.parameters()` 不能完整恢复训练轨迹。

## 三、把一次训练写成状态转移

设 sampler 从 $d_t,r_t$ 产生 batch 索引 $I_t$，模型在 mode $m_t$ 下计算 per-example loss。一次训练可写成

$$
\begin{aligned}
(I_t,d_t',r_t')&=\mathcal S(d_t,r_t),\\
(L_t,b_t',r_t'')&=\mathcal F(\theta_t,b_t,r_t';I_t,m_t),\\
a_t&=\mathcal R(L_t;\rho_t,w_t),\\
g_t^{raw}&=\operatorname{Backward}(a_t),\\
g_t&=\mathcal P(g_t^{raw};q_t,h_t),\\
(\theta_{t+1},s_{t+1})&=\mathcal U(\theta_t,s_t,g_t;h_t),\\
(c_{t+1},q_{t+1},\tau_{t+1})&=\mathcal C(c_t,q_t,\tau_t;L_t,g_t).
\end{aligned}
$$

$\rho_t$ 是 mean/sum/token-weighted reduction，$w_t$ 是 mask/权重，$\mathcal P$ 可包含 accumulation、unscale、clipping 和有限值检查，$h_t$ 包含 LR、momentum、decay 与参数分组。

因此完整的一步是

$$
\boxed{X_{t+1}=\mathcal T_t(X_t;\text{code, data, device}).}
$$

所谓逐步复现，是两次运行从同一 $X_0$ 出发并实现相同 $\mathcal T_t$，而不只是“超参数看起来一样”。

## 四、为什么执行顺序是算法的一部分

混合精度下通常要先 `unscale` 再计算 clipping norm：

$$g^{scaled}=\lambda g
\xrightarrow{\text{unscale}}g
\xrightarrow{\text{clip}}\widetilde g.
$$

若先裁剪 $g^{scaled}$，阈值实际被 loss scale $\lambda$ 改写。类似地：

- decay 在 gradient 内还是 parameter update 上，决定 coupled L2 还是 decoupled decay；
- scheduler 在 `optimizer.step()` 前还是后，决定第一步实际 LR；
- clip 每个 micro-batch 还是累积后一次，因非线性而一般不等价；
- overflow 时跳过 optimizer step，scheduler 和 step counter 是否也跳过必须声明。

> [!definition] 一步更新合同
> 至少固定：目标与 reduction、batch/sampling、forward mode、随机状态、backward/accumulation、gradient transforms 的顺序、optimizer 方程和初始化、参数分组、scheduler 时点、precision/overflow 语义、所有 step 计数。

## 五、一个可手算的完整状态转移

线性模型 $\widehat y=\theta x$，单样本平方损失 $\ell_i(\theta)=\tfrac12(\theta x_i-y_i)^2$。取 $\theta_0=0$，batch 为 $(x,y)=(1,1),(2,0)$，mean reduction：

$$
\begin{aligned}
\nabla\ell_1(0)&=(0\cdot1-1)1=-1,\\
\nabla\ell_2(0)&=(0\cdot2-0)2=0,\\
\widehat g_0&=(-1+0)/2=-0.5.
\end{aligned}
$$

无 momentum、无 decay、$\eta=0.2$ 时，$\theta_1=0-0.2(-0.5)=0.1$。若使用 momentum $\mu=0.9$ 且 buffer 从零开始，则首个 buffer 为 $-0.5$；若框架把首个 buffer 初始化为第一梯度，数值恰相同，但加入 dampening 后从第二步起约定差异出现。

## 七、在 AI 训练中的张量合同

以语言模型为例：token ids 为 $[B,T]$，logits 为 $[B,T,V]$，有效 token mask 为 $[B,T]$。若 loss 按有效 token mean，分母是 $M=\sum_{b,t}mask_{bt}$，并非固定 $BT$。梯度是参数张量族：embedding $[V,d]$、attention projection $[d,d]$、bias $[d]$；global norm 必须说明是否跨所有参数、所有 rank 规约。

模型训练还会调用：

- dropout/augmentation 的随机流；
- normalization 的即时统计或 running buffer；
- gradient scaler 的 overflow 状态；
- distributed sampler 的 shard 与 epoch；
- optimizer state checkpoint 的 dtype/shape。

## 八、三种不同的“等价”

| 等价层级 | 需要相同什么 | 常见反例 |
|---|---|---|
| estimator 等价 | $\widehat g$ 逐点/同分布 | sampling 与 reduction 不同 |
| 单步 update 等价 | $\Delta\theta_t$ 相同 | optimizer state 不同 |
| trajectory 等价 | 全部 $X_t$ 相同 | RNG、buffer、schedule 分叉 |
| 统计结果等价 | 指标分布在容差内 | seed 数不足、硬件 nondeterminism |

“期望梯度相同”只给 estimator 的一阶矩，不保证单次 update、轨迹或最终模型相同。

> [!research] 前沿地位
> 状态机表述是工程与数学建模的稳定框架；特定深网轨迹的可预测性、跨硬件 bitwise reproducibility、随机 kernel 对最终模型分布的影响仍是系统—优化交叉问题。不能从“非确定”推导“不可复现”，也不能从一个 seed 的相同 loss 推导完整状态相同。

## 十、本节回顾

- 训练步的基本对象是完整状态 $X_t$，不只是 $\theta_t$；
- reduction、处理顺序、buffer 初始化和 step 计数都是算法的一部分；
- “同优化器”必须落到明确更新方程和实现合同；
- estimator、单步、轨迹与统计等价是四个不同声明；
- 下一节 [[Mini-batch 梯度、平均求和与有效 Batch]] 将把 $\widehat g_{B,t}$ 的尺度与方差完全展开。

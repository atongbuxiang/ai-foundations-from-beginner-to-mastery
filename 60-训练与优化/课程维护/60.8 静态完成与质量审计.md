## 二、内容边界审计

本卷知识链已经闭合为：

$$
\text{format fields}
\to \text{tensor dtype/quantizer contract}
\to \text{estimator and step clocks}
\to \text{process mesh and collectives}
\to \text{memory/critical path}
\to \text{quality, reproducibility and causal evidence}.
$$

正文、题解或实验已经明确以下边界：

- dtype 不是一个足够的训练算法标签；storage、multiply input、accumulation、reduction、update/state 与 checkpoint 可以不同，完整结论还受 backend、kernel、scale、FTZ 和特殊值语义约束；
- exponent bits 主要控制 range，significand precision 控制同一 binade 的 spacing；BF16 可有接近 FP32 的 range，却在 1 附近只有 $2^{-7}$ ulp；TF32 是常见 GEMM/conv 执行 policy，不等于通用 storage dtype；
- 低精度点积至少包含输入/乘法量化与部分积累加两类误差；FP32 accumulate 只降低后者，不抹去低精度输入误差或 cancellation 条件数；
- FP8 的 E4M3/E5M2、scale granularity、amax history、delayed/current scaling、异常值和高精度保留组共同定义 estimator；bit 数不能单独推出稳定性或硬件速度；
- loss scaling 在精确算术下由链式法则恢复原梯度，但有限精度会改变 underflow/overflow 和控制流；正确顺序是 unscale→finite/inspect→clip→step；
- FP32 master weight 解决 parameter-update ulp，loss scaling 解决 backward range，gradient accumulation 解决 batch estimator，三者不能互相替代；
- attempt、backward、successful update、scheduler、EMA 与 scaler 是不同 clocks；overflow 发生时各 rank 必须通过 global consensus 同步 skip，否则参数和 optimizer state 分叉；
- accumulation 与 DDP 必须在 micro-step×rank 二维账中同时保留 gradient sum 和有效 sample/token count；只除 micro-step 数、rank 数或总 GPU 数都可能改变目标；
- stochastic rounding 满足 $\mathbb E[Q(x)\mid x]=x$ 与 $Var\le\Delta^2/4$，这是局部一步命题；状态依赖梯度、非线性、clipping、选择和相关 RNG 阻止它自动升级为轨迹或决策无偏；
- PTQ、QAT 与真实低精度训练是三类路径；QAT 的 STE 是人为优化 surrogate，不是 $round$ 的真实导数；weight、activation、gradient、state 和 collective payload 是五个需分账的量化对象；
- 理想 mixed-precision Adam 的 16 B/parameter 与 state 压缩节省只描述 persistent model states；activation、scale metadata、temporary buffer、allocator 与实际 kernel 决定 peak memory/time；
- data parallel 的正确全局 mean 是 $\sum_rs_r/\sum_rn_r$；average of local means 只在 count 相等或显式加权时等价；global batch 只乘 DP degree，不乘 TP/PP/EP 所占总设备；
- ring All-Reduce 的 $2(P-1)M/P$ 是 payload 模型，不固定 NCCL 在任意 topology 的算法；bucket-ready、latency、bandwidth、contention 与未遮蔽尾巴决定 step overhead；
- column/row TP、PP、SP/CP 与 EP 必须写被切 tensor、local shape、group、collective 和同步点；并行度乘积、术语缩写或稀疏 FLOPs 都不保证可执行或负载均衡；
- pipeline 的 $M/(M+P-1)$ 是均衡简化模型；增加 micro-batch 还会改变 kernel efficiency、activation residency、通信和 optimizer normalization；
- ZeRO/FSDP 的稳态分片不能替代 $M_{peak}=\max_t\sum_jM_j(t)$；full-parameter gather、activation、gradient bucket、workspace、prefetch 与 allocator 都可使 $16N/P$ 之外再次 OOM；
- activation checkpointing 用 recompute 和 RNG 重放复杂性换显存；offload 用链路时间、host/NVMe 资源和 prefetch 调度换 device capacity；两者必须以关键路径与 time-to-quality 验收；
- Roofline 的 $\min(C,BI)$ 是上界，strong-scaling efficiency 必须使用同 workload 的实测 baseline；peak FLOPs、sum of communication kernels、tokens/s 和 time-to-quality 是不同对象；
- floating reduction 非结合、并发、kernel、RNG、数据/故障和软件硬件共同构成非确定性来源树；bitwise、numerical、trajectory 与 decision reproducibility 不是同一门槛；
- E0 manifest、E1 counters、E2 profiler、E3 matched learning curve、E4 paired repeats/CI 与 E5 causal intervention 回答不同问题；没有 E3 不以速度推出质量，没有 E5 不把相关/单 trace 提升为根因。

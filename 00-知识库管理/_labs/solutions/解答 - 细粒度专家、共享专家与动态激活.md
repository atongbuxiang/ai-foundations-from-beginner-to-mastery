# 解答 - 细粒度专家、共享专家与动态激活

## A. 识别与复述

### ARCH-EXPERT-A01
Shared 改变每 token 必经的 dense baseline；fine-grained 把固定预算切成更多更窄候选；dynamic $k$ 改变逐 token routed assignment 数。它们分别主要改变 always-on cost、组合/执行粒度和预算分配。

### ARCH-EXPERT-A02
这是解释性假说 `H`。Shared 按定义高频激活不能证明其内容是公共知识；需控制预算并做表示、干预和跨 seed 稳定性实验才可升级为 `E` 支持。

### ARCH-EXPERT-A03
Token-side 令每 token 自主选 $k_t$ 并受总预算；expert-side threshold/quantile 让每 expert 满足 quota，逐 token 行和只是结果。一个约束行预算，一个约束列容量。

## B. 手算与建模

### ARCH-EXPERT-B01
$E'=rE=32$，$m'=m/r=1024$，$k'=rk=8$。于是 $E'm'=Em$、$k'm'=km$，忽略 Router/系统成本时总参数与激活主 MAC 保持。

### ARCH-EXPERT-B02
总参数为
$$2dm_s+E2dm_e=2{,}097{,}152+16{,}777{,}216=18{,}874{,}368.$$
逐 token 主 MAC 为 $2dm_s+k_t2dm_e=2{,}097{,}152+3{,}145{,}728=5{,}242{,}880$。

### ARCH-EXPERT-B03
严格大于 $.4$ 的是 $.91,.72,.48$，故 $k_t=3$；严格大于 $.7$ 的是 $.91,.72$，故 $k_t=2$。等于阈值时是否选择也必须声明。

## C. 推导与证明

### ARCH-EXPERT-C01
$E'2dm'=rE\cdot2d(m/r)=E2dm$；$k'2dm'=rk\cdot2d(m/r)=k2dm$。等式只覆盖矩阵乘主项，不覆盖 Router、通信和小矩阵效率。

### ARCH-EXPERT-C02
若第 $r+1$ 个专家给 token $t$ 的边际收益为 $\Delta_t(r)$，理想离散问题为最大化 $\sum_t\sum_{r<k_t}\Delta_t(r)$，约束 $0\le k_t\le k_{max}$、$\sum_tk_t\le B$，并可再加每专家容量。真实难点是反事实 $\Delta$ 未知。

### ARCH-EXPERT-C03
同步时间至少为最忙设备/专家处理时间：$T_{step}\ge\max_iT_i$。两个分配可有同一总 assignment 和 $\mathbb E[k_t]$，但若一个均匀、一个集中，其最大负载不同，故 step time 不同。

## D. 边界、反例与纠错

### ARCH-EXPERT-D01
高 loss 可能来自标签噪声或模型不可表达区域，多给专家不会改善；也可能 Router 已错误选择，增加相似专家只浪费预算。应估计“多一个专家的边际改善”，不是当前 loss 本身。

### ARCH-EXPERT-D02
更多小专家让 Router 输出更大、Top-k 更大、每 expert batch 更小，增加排序、消息、kernel launch、padding/块碎片并降低 GEMM utilization。因此主 MAC 相等仍可更慢。

### ARCH-EXPERT-D03
若一次同时增加 shared path、切细专家、改变 $k_t$ 与 balance，质量/吞吐差异是整个组合的总效应。没有因子消融或 matched-budget 对照，无法识别任一组件的独立因果贡献。

## E. AI 迁移

### ARCH-EXPERT-E01
做 shared on/off × coarse/fine × fixed/dynamic $k$ 八格，多 seed；分别给等总参数和等激活 MAC 两条轨道。报告 quality、每层 $k_t$/load、Router cost、expert batch、network、occupancy 与 latency。

### ARCH-EXPERT-E02
训练 matched-budget 模型，对 shared output 做遮蔽、替换或只保留 routed path；按语言/任务/频率测损失变化，并比较 shared/routed 表示 probe、梯度和跨 seed 对齐。若影响广泛且在控制下稳定，才支持“公共”解释。

### ARCH-EXPERT-E03
在小模型上离线枚举 $k=1\dots k_{max}$ 得到每 token 的反事实 loss 曲线，计算 $\Delta_t(k)$；训练 controller 预测该边际值，在固定总 assignment 预算下与 loss/entropy heuristic、随机和固定 $k$ 比较 regret 与 quality。

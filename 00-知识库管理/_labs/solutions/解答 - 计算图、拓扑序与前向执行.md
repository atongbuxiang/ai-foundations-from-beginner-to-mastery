# 解答 - 计算图、拓扑序与前向执行
## A
### NN-CG-A01
计算图用 vertices 表示有类型的 values 或 operations，edges 表示“一个值是另一操作的输入”这种数据依赖；each operation 还必须给出 local function、shape/type 合同和状态语义。execution contract 进一步固定 mode、RNG、mutation、cache 和调度。architecture diagram 只说明宏观模块连接，通常没画 reduction、broadcast、alias 和实际分支，因而不足以唯一决定执行与求导。
### NN-CG-A02
external input 由调用者提供；parameter 跨 batch 保持且由 optimizer 更新；constant 不学习；intermediate 是本次 forward 的派生值；random value 由 RNG 轨迹决定；mutable state 如 running mean 会被程序更新，却不必以 optimizer parameter 身份出现。形状相同不等于角色相同。
### NN-CG-A03
序列 $v_1,…,v_n$ 是 topological order，当每条边 $u\to v$ 都满足 $u$ 先于 $v$。两个没有依赖关系的 ready nodes 可以任意换序，所以一般不唯一；只有偏序恰好强制全序时才唯一。
## B
### NN-CG-B01
边为 $x_1\to a,x_2\to a,x_1\to b,a\to c,b\to c,c\to L$。例如 $(x_1,x_2,a,b,c,L)$ 和 $(x_2,x_1,b,a,c,L)$ 都合法。在 $(2,3)$，$a=6$，$b=\sin2\approx0.909297$，$c\approx6.909297$，$L\approx47.73838$。每一步都只在所有 parents 就绪后执行。
### NN-CG-B02
初始 indegree 为 $A:0,B:0,C:2,D:1,E:2$，ready $=\{A,B\}$。若先取 $A$，ready $=\{B\}$；取 $B$ 后 $C,D$ 同时就绪，ready $=\{C,D\}$；两者任意顺序取完后 $E$ 就绪。因此 $A,B,C,D,E$ 和 $B,A,D,C,E$ 都是答案。
### NN-CG-B03
显式图是 `matmul(X,W)→M`、`broadcast(b)→B_b`、`add(M,B_b)→Z`、`ReLU(Z)→H`、`square(H)→Q`、`reduce_mean(Q)→L`。若 $X:[B,d_{in}]$、$W:[d_{in},d_{out}]$，则 $M,Z,H,Q:[B,d_{out}]$、$b:[d_{out}]$、$L:[]$。backward 可保存 $X,W$、ReLU mask（或 $Z/H$）、reduction element count；$M,Q$ 不一定需保存。
## C
### NN-CG-C01
任意有限 DAG 至少有一个 indegree-zero node：否则从任意节点不断沿入边逆追，有限节点会导致重复，从而得到 cycle。删掉 zero-indegree node 不会给剩余图创造 cycle，归纳可得 Kahn 处理全部节点。反之，若算法停滞且仍有节点，剩余每点 indegree 至少为 1，同样的逆追论证产生 cycle。
### NN-CG-C02
对任一节点 $v$，它的值由 parents 的值和固定局部纯函数唯一确定。按偏序高度归纳：sources 相同；若所有 parents 在不同合法序中已得到相同值，$v$ 也必相同。故 outputs 相同。结论依赖纯函数、精确算术与固定随机/状态语义；浮点 reduction 顺序会破坏 bitwise 相同。
### NN-CG-C03
符号图只创建一个 parameter value $W$，它通过 $T$ 条边输入不同 operation calls。如果换成 $W_1,…,W_T$，函数类会扩大，参数槽位也从一份变成 $T$ 份，已是另一模型。一个 $W$ 的 fan-out 保证 forward 共用同值，reverse 则将各调用对该唯一 value node 的贡献求和。
## D
### NN-CG-D01
$h_t=F(h_{t-1})$ 若在不带时间索引的静态图中画成 $h\to F\to h$，就有 cycle，无 topological order。给定有限 horizon $T$ 后展开成 $h_0\to h_1\to\cdots\to h_T$，每个 time-indexed value 是新节点，图恢复为 DAG；共享的 $F$ 参数仍是同一 parameter node。
### NN-CG-D02
数学上无依赖的操作可交换，但 GPU scheduler、kernel fusion、memory locality 和 critical path 使 latency 不同。并行浮点 sum 不结合，原子加的完成顺序也可变，所以数学等价不意味 bitwise 等价。
### NN-CG-D03
例如 $y=x^2$、随后执行 `x.zero_()`。backward 需要原始 $x$ 计算 $2x\bar y$，若 tape 只指向已覆盖 storage，会错返 0。version counter 可检测 saved tensor 被修改并拒绝 backward；functionalization 将 mutation 重写为新 value，保留 SSA 式语义。
## E
### NN-CG-E01
记录 train/eval mode、drop probability、mask shape/dtype/device、RNG algorithm、global seed、counter/key 以及每个 device/rank 的 stream 分配。严格重现可直接保存 mask；重算时则必须回放相同 counter/order，不能只记一个初始 seed。
### NN-CG-E02
给 embedding value node 注册两类 call-site ID：lookup 分支的 sparse row contributions 和 output-projection 分支的 dense matrix contribution。hooks 分别导出两者，检查形状、被访问 rows、norm 和和值；最终验证 parameter `.grad` 等于两个贡献之和，并用 untied 对照试验防止误合并。
### NN-CG-E03
需固定输入、branch predicate、loop trip count、RNG/state 并保存 executed trace；说明对当次 trace 求导还是对平滑 surrogate 求导；在 branch boundary 两侧分别做 finite difference；检查 mutation/alias 版本；对重算前后的 trace、forward value 和 VJP 做一致性比较。

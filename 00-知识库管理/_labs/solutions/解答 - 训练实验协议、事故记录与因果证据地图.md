# 解答 - 训练实验协议、事故记录与因果证据地图

## A. 识别与复述

### TRN72-A01
Claim ID、可检验陈述、treatment/control 版本、experimental unit、outcome、estimand、target distribution/scope、practical margin、竞争解释与最高允许证据语言。还应链接 protocol 和 evidence rows。

### TRN72-A02
Protocol 是运行前设计与分析承诺；manifest 固定单次 run 的 code/config/data/seed/env/budget 身份；event ledger 追加运行时间线；trial ledger 保存搜索空间、预算、失败与选择；postmortem 对事故影响、first bad、机制、修复和行动项作独立审计。

### TRN72-A03
Integrity 检查文件/hash/schema；same-code 在声明环境重跑；reimplementation 依据合同另写实现；statistical replication 在新随机单位回收效应分布；external validity 在新 data/model/scale/hardware 范围检验。层级越高不自动包含所有低层细节，但不能用 seed=42 替代。

## B. 手算与构造

### TRN72-B01
例 `C-OPT-01`：在 7B family、data-v3、BF16 8×GPU 下，完整 recipe B 相对 A；unit 为 base checkpoint×data seed block 的 launched run；outcome 为 50B effective tokens 的 locked validation NLL；estimand 为 paired mean difference；margin -0.02；scope 限该 family/版本/硬件，另报 failure 和 time。

### TRN72-B02
Symptom：12:04 loss NaN；first bad：需从 telemetry/replay确定，如 12:03:41 layer 18 unscaled gradient Inf；trigger：具体 batch/length；mitigation：临时降 LR 后运行；root cause 尚是候选，可能 reduction、数据或 state；必须用原现场复现和单因素反事实验证。

### TRN72-B03
Launched denominator=6，success=4/6，NaN=1/6，timeout=1/6；质量/时间对成功 runs 可描述但必须标 conditional-on-success，同时给 intention-to-run 固定预算成功率和两类 failure。若 timeout 是未达 target，按预注册右删失处理。

## C. 推导与证明

### TRN72-C01
Hash 是字节串的指纹：相同 hash 强力支持相同 bytes，不判断算法是否实现 intended equation、数据是否合规、metric 是否泄漏或 estimand 是否正确。语义需 oracle、review、实验和统计证据。

### TRN72-C02
E2 见 A 变化后 M、Y 依次变化，但共同原因 U（data mix/calendar/backend）可同时推动 A/M/Y，或 M 只是副产物。E3 的随机 assignment/配对干预使替代路径在设计上被控制，并估计 treatment effect；观察先后没有这层 assignment。

### TRN72-C03
若看到结果后只延长表现差的 run、换 metric 或删坏节点，deviation 与 outcome 相关，选择偏差进入分析。Primary 按原 protocol/intention-to-run 保留；另作 per-protocol、排除/加权和 worst-case sensitivity，并标 deviation 版本。

## D. 边界、反例与纠错

### TRN72-D01
还需数据/环境、依赖、RNG、selection、tuning budget、失败、命令与硬件；代码可能不可执行或 nondeterministic，checkpoint 也只是一条获胜路径。可复现对象与层级必须明确。

### TRN72-D02
Blameless 是不把复杂系统事故简化为个人指责；行动仍需 owner、截止、验证测试和关闭条件，否则系统不会改变，也无法追踪风险。

### TRN72-D03
账本可完整记录一个错误 DAG、低功效 study 或泄漏 outcome。完整性提高可审计/纠错性，不替代识别假设、随机化、统计不确定性与外部复验。

## E. AI 迁移

### TRN72-E01
目录可分 `claims/C-*.yaml`、`protocols/P-*/`、`runs/R-*/manifest+events`、`incidents/I-*`、`analyses/A-*`、`decisions/D-*`；所有记录用稳定 ID，artifact 表含 path/URI、SHA-256、schema、producer run/event、owner/retention。Claim-evidence matrix 双向链接 analysis/run/artifact。

### TRN72-E02
必须有真实 failure 的 launched record、影响与完整 timeline；最后正常/首异常 checkpoint、batch/data cursor、RNG/env；first-bad 定位；replay-A/B/control-C/quality-D；mitigation/permanent fix；回归 invariant；失败分母；owner/action；未解竞争解释；artifact hashes 与独立复跑说明。

### TRN72-E03
更快：claim 固定 target quality 的 wall-time，E0 计时合同→E2 trace→E3多 run target-time→E5新硬件；更稳：claim fixed-budget failure probability，E0 failure taxonomy→E2 incident timeline→E3 paired launched runs→E5新 seeds/data；更准：claim locked-test effect，E0 selection/estimand→E1 metric oracle→E3 factorial/paired CI→E4机制干预→E5新任务。三条预算、outcome 和证据不可合成一句口号。

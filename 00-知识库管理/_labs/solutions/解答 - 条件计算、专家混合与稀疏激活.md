# 解答 - 条件计算、专家混合与稀疏激活

## A. 识别与复述

### ARCH-MOECAP-A01
Dense FFN 有 $P=C_{token}\approx2dm$；MoE 有 $P_{expert}\approx E\,2dm_e$，但理想逐 token 专家主计算为 $C_{token}\approx k\,2dm_e$。解耦来自 $E$ 与 $k$ 是两条轴。

### ARCH-MOECAP-A02
Total 是 checkpoint 中全部参数；activated 是某 token 前向实际调用的子集；resident 是为执行而驻留某设备/内存层级的权重；MACs 是实际算术。未激活权重仍可驻留，激活权重也可能因复用、通信和 kernel 产生与参数数目不成比例的时间。

### ARCH-MOECAP-A03
条件计算先根据 $x$ 选出 $I(x)$，只计算 $i\in I$ 的专家；普通 dense ensemble 先计算全部成员再组合。前者的计算图支持集随输入变化，后者通常固定。

## B. 手算与建模

### ARCH-MOECAP-B01
参数与每 token 主 MAC 都为
$$2dm=2\cdot1024\cdot4096=8{,}388{,}608.$$
这不含偏置、激活和 residual/norm。

### ARCH-MOECAP-B02
总专家参数为 $16\cdot2\cdot1024\cdot1024=33{,}554{,}432$；激活专家 MAC 为 $2\cdot2\cdot1024\cdot1024=4{,}194{,}304$。相对 dense 的 $8{,}388{,}608$，分别为 $4\times$ 与 $0.5\times$；还未计 Router/dispatch。

### ARCH-MOECAP-B03
总容量比例 $Em_e/m=8/2=4$；激活计算比例 $km_e/m=2/2=1$。一个计所有 $E$ 个专家，另一个只计被选 $k$ 个，故不矛盾。

## C. 推导与证明

### ARCH-MOECAP-C01
参数倍数
$$R=\frac{E2dm_e}{2dm}=\frac{Em_e}{m},$$
故 $Em_e=Rm$。若还要求专家主 MAC 与 dense 相等，则 $km_e=m$。两式合并得 $E/k=R$。

### ARCH-MOECAP-C02
令 $v_i=f_i(x)$，则
$$\left\|\sum_i v_i\right\|^2=\sum_i\|v_i\|^2+2\sum_{i<j}v_i^Tv_j.$$
两两正交时交叉项全为零；非正交时正/负相关项可放大或抵消，所以不能只按单专家范数选取而不看夹角。

### ARCH-MOECAP-C03
若 shared 总宽 $m_s$，则 $P\approx2dm_s+E2dm_e$，逐 token 主 MAC 为 $2dm_s+k2dm_e$。shared path 对每个 token 都执行，故其成本不随路由稀疏度下降。

## D. 边界、反例与纠错

### ARCH-MOECAP-D01
$2/64$ 只描述被选 expert fraction。训练仍需全部专家参数、梯度与 optimizer state；推理也可能将全部专家复制或按 EP 分片。显存取决于 placement、dtype、缓存和并行副本，不等于 activated fraction。

### ARCH-MOECAP-D02
令所有专家初始化/训练后几乎相同，Router 只在冗余副本间选择，则 total parameters 增加而函数容量没有有效利用。也可因数据不足、专家饿死或优化不稳，使额外参数从未学到有用表示。

### ARCH-MOECAP-D03
Decode latency 还受权重是否本地、All-to-All、expert batch size、cache bandwidth、kernel launch、负载尾部和 Router 影响。两个方案 activated parameters 相同，若 placement/topology 不同，延迟可完全不同。

## E. AI 迁移

### ARCH-MOECAP-E01
固定数据、训练 tokens、优化器、总训练步和每 token 实测/理论 FLOPs；调 $E,m_e,k$ 使专家 MAC 与 dense 对齐，并分别报告 total parameters。比较 validation loss、下游任务、seed 方差和 time-to-loss，避免只按单步 FLOPs下结论。

### ARCH-MOECAP-E02
至少分列 total/active/resident parameters、expert/router MAC、activation/optimizer/cache memory、dispatch+combine bytes、padding/drop、kernel occupancy、p50/p95 latency 和能耗。再注明 DP/TP/PP/EP、硬件、dtype 与 sequence/batch。

### ARCH-MOECAP-E03
逐 token 记录 Router scores、所有或抽样专家输出范数与两两夹角，测 rank correlation 和 Top-k recall；训练一个只预测范数的 probe，与原 Router 互换并观察 loss。相关性只能支持关联；互换/干预且控制计算后仍改善，才更接近因果证据。

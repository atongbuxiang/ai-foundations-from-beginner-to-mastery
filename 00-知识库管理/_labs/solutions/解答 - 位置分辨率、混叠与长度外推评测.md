# 解答 - 位置分辨率、混叠与长度外推评测

## A. 识别与复述

### ARCH-EVAL-A01
接受长度是接口/显存允许；数值稳定长度是无 NaN/严重误差；检索长度是能找回远端证据；推理长度是能组合多处证据完成任务；可部署长度还要求吞吐、延迟、内存与可靠性达标。较后层不能由较前层自动推出。

### ARCH-EVAL-A02
长度改变候选数、计算和分布；目标位置改变证据到 query 的距离与“中间丢失”等效应。只扫长度会把位置分布混入均值，只扫位置又不知道规模变化。二维矩阵才能识别长度主效应和位置交互。

### ARCH-EVAL-A03
Perplexity 测分布平均 token 预测；needle 测受控信息定位；LongBench 类综合真实任务但模板/裁剪和指标各异；吞吐/显存测系统代价。前两者不充分覆盖复杂推理，任务集也不能代替系统测量，系统快更不等于答案正确。

## B. 手算与建模

### ARCH-EVAL-B01
$3\times3\times4\times3=108$ 个实验 cell；每 cell 200 样本，共 $21{,}600$ 次样本运行。

### ARCH-EVAL-B02
总和 6.10，均值 $6.10/9\approx0.678$，最差为 .10。三档长度均值分别 $(.95+.90+.70)/3=.85$，$(.92+.78+.45)/3\approx.717$，$(.80+.50+.10)/3\approx.467$。总均值隐藏了最长/尾部崩溃。

### ARCH-EVAL-B03
A 吞吐 $64k/8=8k$ token/s，B 约 $5.33k$ token/s。A 更快但多用 12 GB；选择还依并发、硬件上限、成本、延迟 SLO 与稳定性，不能只按 throughput 或 memory 一项决定。

## C. 推导与证明

### ARCH-EVAL-C01
若整段平均 loss 随长度增加，预测目标数和容易/困难 token 组成也变化；候选集合扩大还可引入熵效应。固定同一 target token、前缀任务与评分规则，只改变插入的无关/受控上下文和目标位置，使比较更接近“同一预测在不同长度/位置”的条件差异。

### ARCH-EVAL-C02
定义 $m\ne n$ 为 $\varepsilon$-碰撞，若对所有频率块 $\|p_i(m)-p_i(n)\|\le\varepsilon$。单块距离满足 $2|\sin(\Delta\phi_i/2)|$；小角度时约 $|\Delta\phi_i|$。若相位计算/存储的绝对误差上界约 $u$，两点距离小于若干倍 $u$ 时不可可靠区分；实际阈值还随维数、归约算法和下游条件数变化。

### ARCH-EVAL-C03
可用 $y=\mu+\alpha_L+\beta_P+\gamma_T+(\alpha\beta)_{LP}+(\alpha\gamma)_{LT}+(\beta\gamma)_{PT}+\varepsilon$，或把长度取 log 后做回归。$LP$ 交互检验某位置劣势是否随长度扩大；应有重复 seed/样本估计误差，避免把单 cell 噪声当结构效应。

## D. 边界、反例与纠错

### ARCH-EVAL-D01
一次 needle 可能有固定模板、唯一字符串匹配、答案靠近末端或偶然成功；它没测位置全覆盖、多证据推理、干扰鲁棒性、重复试验和系统成本。合理表述只能是“在该协议的一次/若干样本上可接受 1M 输入并成功检索”。

### ARCH-EVAL-D02
例如九个 cell 八个为 1.0、最长长度中间位置为 0，总均值仍 .889。若实际应用关键证据常在该 cell，系统不可用。应同时报告完整矩阵、最差/分位数、按长度/位置分层与失败样例。

### ARCH-EVAL-D03
Tokenizer 改变 token 长度；模板改变目标距离；截断可能直接删除证据；解码 temperature/stop 改输出；低精度 cache 改数值。若这些与位置方法同时改变，观察差异无法唯一归因，因此必须版本锁定并记录。

## E. AI 迁移

### ARCH-EVAL-E01
每行记录模型/checkpoint、位置方法、训练长度与 token；列为输入长度、target 绝对/相对位置、任务/干扰、accuracy/loss、NaN/失败类型、prefill/decode latency、tokens/s、峰值显存/cache bytes、dtype/kernel、seed 与置信区间。另给最差 cell 和短程回归。

### ARCH-EVAL-E02
从版本化配置重建 $\omega_i$，在预定位置集合或分块搜索所有位置对；以 fp64 参考和目标 dtype 分别计算相位/编码距离，按事先设定绝对+相对容差报告最近对、距离、频率块贡献。记录 base、rotary dimension、scale、相位归约实现、硬件与代码 commit，不能只输出“无碰撞”。

### ARCH-EVAL-E03
最低门槛应包含：接口与数值稳定；覆盖至 128k 的长度×位置、多任务、多 seed；必须远程依赖的干预验证；短长度不显著回归；full/cache 一致；在目标硬件的延迟、吞吐、内存和失败率；可复现配置。仅 max_position=128k、一次 needle、低 perplexity 或“公式可算到 128k”均不足以单独声明支持。

# 解答 - 训练系统的对象、状态与一步更新合同

> [!warning] 使用边界
> 先独立写出状态和运算顺序。读懂清单不等于能从真实训练代码恢复合同。

## A. 识别与复述

### TRN01-A01
$\theta_t$ 是 trainable parameters；$b_t$ 是模型非参数 buffer；$s_t$ 是 optimizer state；$r_t$ 是 RNG；$d_t$ 是 sampler/data iterator；$c_t$ 是 scheduler/controller；$q_t$ 是 dtype、loss scale、overflow 等数值状态；$\tau_t$ 是 micro-step、optimizer-step、seen tokens 等计数。

### TRN01-A02
Estimator 等价只要求 gradient estimator 逐点相等或同分布；单步等价还要求处理后的 direction 与 optimizer state 给相同 $\Delta\theta$；trajectory 等价要求所有后续完整状态相同；统计等价只要求选定指标分布在预设容差内，不要求逐步相同。

### TRN01-A03
至少还要相同：optimizer buffer/step、BatchNorm running statistics、data permutation/cursor、CPU/GPU RNG、dropout/augmentation RNG、scheduler、loss scaler/overflow 和 token/optimizer counters。任一项不同都可能让下一步分叉。

## B. 手算与构造

### TRN01-B01
Mean gradient $=3$，所以 $\theta^+=1-0.1(3)=0.7$。Sum gradient $=6$，所以 $\theta^+=0.4$。要匹配 mean update，令 $6\eta_{sum}=0.3$，得 $\eta_{sum}=0.05=0.1/2$。

### TRN01-B02
预测为 $0,0$；losses 为 $\tfrac12,0$，mean loss $=0.25$。Gradients：$(0-1)1=-1$ 与 $(0-0)2=0$，batch mean gradient $=-0.5$。因此 $\theta_1=0-0.2(-0.5)=0.1$。检查：mean reduction 对 loss 和 gradient 都除以 2。

### TRN01-B03
一个合格 manifest 可含：

```yaml
model: {weights: ckpt/model, buffers: included, mode: train}
optimizer: {name: SGD, state: ckpt/optim, param_groups: ..., step: 1200}
scheduler: {state: ckpt/sched, call_order: after_optimizer}
sampler_rng: {sampler_epoch: 3, cursor: 4096, cpu_rng: ..., device_rng: ...}
precision: {param_dtype: bf16, accum_dtype: fp32, loss_scale: 65536, overflow: false}
counters: {micro_step: 4800, optimizer_step: 1200, seen_tokens: 8.1e9}
```

真实文件还应记录代码 commit、框架/kernel/hardware 和 data version。

## C. 推导与证明

### TRN01-C01
确定性函数的定义给 $X_t=X_t'$ 时 $\mathcal T_t(X_t)=\mathcal T_t(X_t')$，故 $X_{t+1}=X_{t+1}'$。以此为归纳步：若 $X_0$ 相同且每个 $\mathcal T_t$ 相同，则对所有 $t$ 状态相同。若随机性没有收入 $X_t$，$\mathcal T_t$ 就不是给定输入上的确定函数，证明不成立。

### TRN01-C02
令标量 $g=2$、scale $\lambda=100$、threshold $c=1$。先 clip scaled gradient：$\operatorname{clip}_1(200)/100=1/100$；先 unscale：$200/100=2$，再 clip 得 1。二者不同。原因是 clipping 是非线性齐次度 0/1 分段映射，不能与任意 scale 自由交换。

### TRN01-C03
可写

$$
X_{t+1}=\mathcal C\circ\mathcal U\circ\operatorname{clip}
\circ\operatorname{unscale}\circ\operatorname{accumulate}
\circ\operatorname{backward}\circ\mathcal R\circ\mathcal F\circ\mathcal S(X_t).
$$

若 overflow，通常跳过 $\mathcal U$ 并更新 loss scaler；scheduler、optimizer step counter、EMA 和 seen-token counter 是否推进必须分别声明，不能用一个“step”概括。

## D. 边界、反例与纠错

### TRN01-D01
一维 BatchNorm eval，令 $\gamma=1,\beta=0$，两个模型参数相同，但 running means 分别为 0 与 1、running variance 都为 1。输入 $x=0$ 时输出近似 0 与 $-1$，所以参数相同不保证模型函数相同。

### TRN01-D02
相同 final training loss 不推出：参数/函数相同（多个 minimizer）；trajectory 相同（不同路径到同一 loss）；validation/generalization 相同；optimizer state 相同；下一步相同；甚至 compute 相同。它只是一个标量观测相同。

### TRN01-D03
某些 scheduler 假定先完成第一个 optimizer step 再递增 epoch/step；反序可能跳过初始 LR 或提前衰减。应查看框架版本文档、scheduler state 的 `last_epoch`、optimizer 各 param-group 实际 LR，并用前两步日志/单元测试确认，而非凭惯例猜测。

## E. AI 迁移

### TRN01-E01
logits $[B,T,V]$、targets/mask $[B,T]$。先得到 token losses $[B,T]$，目标应明确为

$$L=\frac{\sum_{bt}m_{bt}\ell_{bt}}{\sum_{bt}m_{bt}}.$$

跨 micro-batches/ranks 应累计 numerator 和真实 nonpad denominator；gradient accumulation 最后只 step 一次；global token counter 加所有 rank 的有效 token 数，而不是固定 $BTW$。

### TRN01-E02
逐步 hash/保存：batch ids 与 masks → forward outputs/loss numerator/denominator → selected raw parameter gradients → unscaled/clipped gradients与 norm → optimizer buffer/step → $\Delta\theta$。找到第一处超容差分叉后检查该节点的输入状态，避免从最终 loss 反向猜。

### TRN01-E03
仍需 collective reduction tree、kernel determinism、GPU/driver/library、compiler/fusion、sharding、async data order、atomic operations、dtype/TF32、loss scaling、rank RNG、checkpoint restore 和硬件故障恢复路径。相同 seed 只固定被正确管理的随机流，不约束非确定 kernel。

# 解答 - 解码质量、延迟、吞吐、随机性与证据地图

## A. 识别与复述

### LM56-A01
Raw model 是固定 history 下的 logits/$p_\theta$；decoder 是 processors、constraints、search/sampler、RNG 和 stop 定义的序列过程；serving system 再加入 queue、prefill/decode、KV、batch、kernel、hardware 和故障。主张必须指出干预哪层、固定哪层。

### LM56-A02
TTFT 是 arrival 到首 token；TBT 是相邻流式 token 间隔，TPOT 常为首 token 后平均每输出 token 时间；E2E 是 arrival 到完成；throughput 是单位时间完成请求或 token；goodput 只计算满足指定质量/延迟 SLO 的有效工作。

### LM56-A03
分布复现问理论/实现 sampler 是否同分布；统计复现问有限样本估计和 CI 是否相容；轨迹复现问相同输入/seed 是否得到相同 token bytes。三者强度不同，后者还依赖 RNG 消耗、数值、kernel、batch 和版本。

## B. 手算与构造

### LM56-B01
Request throughput 为 $50/10=5$ req/s；goodput 为 $42/10=4.2$ req/s。SLO pass ratio 为 84%。若另报 token throughput，必须给输出长度与单位。

### LM56-B02
C 与 B 质量同为 .82，但 C latency 更低、cost 更低，故 C 支配 B。C 对 A 质量更高、latency 相同、cost 更低，也支配 A。因此只有 C 不被这两点支配。

### LM56-B03
请求 1 TTFT=100 ms、E2E=400 ms；请求 2 TTFT=$250-50=200$ ms、E2E=$500-50=450$ ms。均值 TTFT=150、E2E=425 ms，但抹平了第二请求更长的 queue/prefill 等待；更多请求时还会隐藏 p95/p99 尾部与分群。

## C. 推导与证明

### LM56-C01
令 $I_i=\mathbf1[\mathrm{TTFT}_i\le\tau_f,\ p99\mathrm{TBT}_i\le\tau_b,\ \mathrm{valid}_i=1]$，窗口 $\Delta$ 内 $G=\sum_iI_i/\Delta$。若 TBT SLO 是逐 token 或请求内最大值，应替换并明确；失败请求仍在到达/完成与 pass ratio 的分母中。

### LM56-C02
不被支配只说明不存在另一候选在全部目标上不差且至少一项更好。两个点可一个质量高但成本高、另一个相反，均在前沿；选哪个需要 SLO 或效用权重。Pareto 偏序本身不给唯一全序。

### LM56-C03
同一 prompt 在两 decoder 下配对，能消去 prompt 难度的共同变异；若可定义耦合 seed，还可减少随机样本差异，比较每对差值并 bootstrap。它不保证两 decoder 的 seed 具有相同语义，也不替代多 seed、分布检验或处理 carryover/服务背景负载。

## D. 边界、反例与纠错

### LM56-D01
从同一分布独立采样也常产生不同文本；两个 distribution-exact 算法可因 RNG 调用顺序不同而在同 seed 下分叉。需要多样本频率/理论枚举检验分布。相反，同一条文本也可能是不同分布的偶然交集。

### LM56-D02
无法判断它使用 output/total tokens，是否在极端 batch、短输出、离线无到达队列或不可接受尾延迟下取得。必须给 model/hardware、batch/concurrency、arrival process、prompt/output 分布、warmup、计时边界、TTFT/TBT/E2E 分位和 SLO goodput。

### LM56-D03
这会形成 survivorship bias：OOM、timeout、invalid 往往正是最慢/最差请求，删除后 latency 和质量都虚高。应分别报总到达、完成、失败类型、重试；失败计入 failure/SLO miss，并预注册 censored latency 的处理。

## E. AI 迁移

### LM56-E01
预先定义模型/decoder/server 干预、数据与切片、prompt/output/arrival 分布、参数调优预算、质量/安全/validity、TTFT/TBT/goodput/成本主指标、样本量/seed/CI、失败和排除规则、硬件/版本、通过阈值与停止条件；测试集前冻结配置。

### LM56-E02
用固定可回放 arrival trace，在一组递增 arrival rates/concurrency 上稳态运行、预热并重复；每点报告 queue、TTFT/TBT/E2E p50/95/99、throughput、SLO goodput、KV/OOM/error。一直扫过吞吐平台与尾延迟拐点，不能只停在最佳点。

### LM56-E03
把“更好”改为：在指定 checkpoint、硬件、版本、任务集、arrival/长度分布和 SLO 下，C 的主质量指标非劣于 B 的预注册 margin，且 p99 TTFT、p99 TBT、goodput、显存/成本满足阈值；用配对 CI 和多轮系统重复检验。公开原始 trace、失败与参数；任何主条件失败即可证伪。

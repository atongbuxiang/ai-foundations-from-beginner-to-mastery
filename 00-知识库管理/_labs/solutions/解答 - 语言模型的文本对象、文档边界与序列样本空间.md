# 解答 - 语言模型的文本对象、文档边界与序列样本空间

> [!warning] 使用边界
> 先自己画出类型明确的函数链；能背字段不等于能从真实数据管线定位边界泄漏。

## A. 识别与复述

### LM01-A01
$D_{enc}$：bytes→Unicode string，记录 encoding/error policy；$N$：string→处理后 string，记录 Unicode/form/空白控制；$S_{doc}$：stream→documents，记录 parser/boundary；$A_{tok}$：document→IDs，记录 tokenizer 文件与 special tokens；$W$：streams→固定窗口、position/attention/loss masks，记录长度、stride、packing。复合函数的每个输出都是下一步输入，任一步多对一都会影响可逆性。

### LM01-A02
文档是内容边界单位；token stream 是其编码序列；窗口是模型一次接收的固定/上限长度数组；batch 是多个窗口的执行张量；有效 target token 是真正进入 loss denominator 的位置。五个数量通常不同。

### LM01-A03
EOS 是长度的停止事件。对长度 $t$ 文档：$\prod_{i<t}p(x_i|x_{<i})p(EOS|x_{<t})$。删除 EOS 后只学条件 token，不学这个终止因子，停止由外部规则决定。

## B. 手算与构造

### LM01-B01
独立文档可写 `[BOS,A,B,EOS]`、`[BOS,C,EOS]`，labels 通常屏蔽 BOS，故 masks `[0,1,1,1]`、`[0,1,1]`。直接拼接可为 `[A,B,C]`，但让 C 条件于 A,B。长度 6 packing 的一种是 `[BOS,A,B,EOS,BOS,C]`，mask `[0,1,1,1,0,1]`；末尾 EOS 进入下窗或需长度 7。还必须另给 block attention/doc IDs。

### LM01-B02
Token mean $=(4+9)/(2+6)=13/8=1.625$。Document mean $=(4/2+9/6)/2=(2+1.5)/2=1.75$。后者给两个文档相同权重。

### LM01-B03
示例：`raw_uri/hash/snapshot_time`；`encoding/error_policy`；`unicode_version/normalization`；`parser_name/version/options`；`document_id/boundary/EOS_policy`；`tokenizer_model/hash/special_ids`；`window_length/stride/packing/attention_mask/loss_mask`；另加 code commit 与 output manifest hash。

## C. 推导与证明

### LM01-C01
令文档平均 loss $L_i=S_i/T_i$，总 token 数 $T=\sum_iT_i$。则 $\widehat R_{tok}=\sum_iS_i/T=\sum_i(T_i/T)L_i$，权重正比于 $T_i$ 且和为 1。

### LM01-C02
若两管线逐位置给相同 IDs、attention/position/loss masks，模型参数、mode 与 RNG 相同，确定 forward 是同一函数同一输入，故 logits 相同；逐位置 loss 与 numerator/denominator 也相同。若 dropout RNG 或实现非确定，条件缺失。

### LM01-C03
原分布采样文档 $D_i$ 后只含文档内条件 $P(z_{it}|z_{i,<t})$。拼接 $D_i\circ D_j$ 使 $D_j$ 首 token 的条件变成 $P(z_{j1}|D_i)$，而原样本合同中应为 $P(z_{j1}|BOS)$ 或无前缀；这是新条件事件。

## D. 边界、反例与纠错

### LM01-D01
一个 10,000-token 文档以窗口 1,000、stride 1 切分，得到 9,001 个高度相关窗口；另一个短文只有 1 个。把窗口当独立样本会夸大有效样本量并给长文极大权重。

### LM01-D02
即使 B 文档 token 的自身 loss 被屏蔽，若后续被计 loss 的 C 位置可 attention 到 B，B 的信息仍改变 C 的 hidden state/预测；或 B 的 hidden state跨边界进入下一文档。必须同时审计可见性图。

### LM01-D03
同名文件不再唯一对应内容，train/test overlap、token count、许可与实验复现都会漂移。需要 snapshot timestamp、content hash、parser version 与 immutable dataset release；评估应按原始 document identity/hash 去重。

## E. AI 迁移

### LM01-E01
`raw structured messages`→schema validation/role trust→template version→serialized text/special roles→tokenizer normalization/encode→IDs/attention mask→assistant-span labels/ignore mask→packing。每层保存版本与偏移映射。

### LM01-E02
先以 canonical source/document family 分组，再在 group 层做 split；同一 URL 版本、书籍章节或近重复 family 不跨 split。窗口只在 split 后生成；报告 group 数、document 数与 overlap audit。

### LM01-E03
追问 unique raw bytes、unique documents、tokenizer/hash、normalization、BOS/EOS/special count、padding、ignored labels、packing waste、重复 epoch/seen tokens、effective loss tokens、跨 rank 计数、数据 mixture、截断、序列长度与数据版本。

# 习题 - 正则化、交叉验证与模型选择

> [!abstract] 训练目标
> 把 regularized estimator、hyperparameter-selection procedure 与 independent assessment 分开；能推导有限候选选择罚项，实施 nested/structured CV，并识别 preprocessing 与 adaptive-search leakage。

## A. 识别与复述

### LT-CV-A01

区分 model、fitting algorithm、regularization path 与 model-selection procedure。为什么“逻辑回归”不足以定义可复现实验？

### LT-CV-A02

在 nested CV 中分别说明 inner folds、outer test fold 与最终 full-data refit 的职责。

### LT-CV-A03

解释 prediction/estimation 与 model identification 为什么可能偏好不同的交叉验证训练比例。

## B. 手算与数值判断

### LT-CV-B01

有 \(M=20\) 个预声明候选，独立 validation set 大小 \(n_{\rm val}=1000\)，loss 在 \([0,1]\)，\(\delta=0.05\)。计算 simultaneous Hoeffding radius
$$
\epsilon_M=\sqrt{\frac{\log(2M/\delta)}{2n_{\rm val}}}
$$
及 selected oracle 的 \(2\epsilon_M\) 代价。

### LT-CV-B02

样本量 \(n=103\)，做 5-fold CV。说明各 fold 大小可能怎样分配，每次训练样本数是多少；它估计的 procedure 与 full-data refit 有何训练规模差异？

### LT-CV-B03

三个 validation estimates 分别为 \(0.202,0.198,0.201\)，各自 standard error 约 \(0.006\)。按 minimum rule 选谁？若最简模型的 error 在最小值一个 SE 内，one-standard-error rule 可能选谁？还缺什么复杂度顺序信息？

## C. 推导与证明

### LT-CV-C01

用 Hoeffding + union bound 推导独立 validation 上
$$
R(h_{\widehat j})
\le
\min_j R(h_j)+2\epsilon_M.
$$

### LT-CV-C02

写出 K-fold CV estimator，说明它为何通常估计“在约 \((1-1/K)n\) 个样本上训练的 procedure”的风险，而非条件于 full-data fitted model 的风险。

### LT-CV-C03

证明 nested CV 的 outer score 为什么评价“包含 inner selection 的整体 procedure”，而不是只评价最后选中的固定 \(\lambda\)。

## D. 边界、反例与纠错

### LT-CV-D01

标准化器在全数据上拟合后再做 CV。构造信息泄漏路径，并给出正确 pipeline 顺序。

### LT-CV-D02

反驳“5 个 fold errors 是 5 个 i.i.d. observations，所以标准误就是样本标准差除以 \(\sqrt5\)”；指出共享训练数据造成的依赖。

### LT-CV-D03

一个 agent 根据每轮 validation feedback 生成下一个 prompt/model，最终只报告最好结果。为什么固定 \(M\) 的 union bound 未必适用？给出两种合法修复。

## E. AI 迁移

### LT-CV-E01

为同一用户产生多条样本且带时间顺序的推荐系统设计 CV split。说明为什么普通 random row folds 同时违反 group 与 temporal 结构。

### LT-CV-E02

设计 LLM prompt/reranker 的 nested evaluation：至少列出候选生成、inner selection、outer scoring、final refit/selection 与 untouched test 的数据流。

### LT-CV-E03

写一份可审计 model-selection protocol，至少包含十二个字段：sample unit、split、pipeline、search space、metric、seed、stopping、置信预算、refit 与 deployment match 等。

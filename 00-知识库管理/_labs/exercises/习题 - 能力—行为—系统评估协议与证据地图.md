# 习题 - 能力—行为—系统评估协议与证据地图

## A. 识别与复述

### LM64-A01
区分条件模型、生成行为、工具系统和在线产品四层证据。

### LM64-A02
解释 oracle ladder 的作用及其不能证明的因果结论。

### LM64-A03
区分 metric vector、metric tree、硬约束与加权总分。

## B. 手算与构造

### LM64-B01
端到端成功率为 $.50$；替换为 gold retriever 后为 $.70$；再替换为 gold tool output 后为 $.82$。计算两个相邻 oracle gap，并给出谨慎解释。

### LM64-B02
候选系统相对基线质量差 $+1.8$ 分，95% CI 为 $[+.4,+3.2]$；延迟差 $+12$ ms，CI 为 $[-3,+27]$。若质量 superiority margin 为 0、延迟 non-inferiority 上限为 20 ms，判断两扇门。

### LM64-B03
三个 slice 样本量/失败数为 $(100,5),(20,4),(5,2)$。计算各失败率和总体 micro failure rate。

## C. 推导与证明

### LM64-C01
证明任意正权加权总分都可能掩盖某个硬安全阈值被违反。

### LM64-C02
用 potential-outcome 语言说明一次只替换一个模块的 oracle intervention 估计什么比较量。

### LM64-C03
解释 paired evaluation 为何通常比独立两样本比较更有效，并写出差值均值的方差。

## D. 边界、反例与纠错

### LM64-D01
构造离线任务质量提高但在线 goodput 和用户效用下降的系统。

### LM64-D02
反驳“oracle gap 最大的模块就一定最值得工程优化”。

### LM64-D03
说明总体通过而小样本高风险 slice 失败时，为什么不能用总分洗平。

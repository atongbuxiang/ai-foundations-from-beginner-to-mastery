# 习题 - 序列因果性、隐藏状态与递推计算

## A. 识别与复述

### ARCH-STATE-A01
用“两个共享前缀的序列”给出离散因果模型的定义。

### ARCH-STATE-A02
说明 $h_t=F(h_{t-1},x_t)$ 中参数共享带来的两项好处和一项限制。

### ARCH-STATE-A03
解释“固定维状态是历史压缩”以及“任务充分状态”的差别。

## B. 手算与建模

### ARCH-STATE-B01
令 $h_t=0.5h_{t-1}+x_t,h_0=0$，对 $x=(2,-1,3)$ 计算全部状态并写成加权和。

### ARCH-STATE-B02
构造二维状态同时维护输入累计和与最新输入，并给出 update/readout。

### ARCH-STATE-B03
一个 batch 的真实长度为 $(3,1)$，padding 到 3。说明 loss mask 与 state-update mask 应如何设置。

## C. 推导与证明

### ARCH-STATE-C01
证明若两个历史映到同一确定性状态，则任何仅依赖该状态的未来确定性读出都无法区分它们。

### ARCH-STATE-C02
推导标量线性递推 $h_t=ah_{t-1}+bx_t$ 的闭式，并分析 $|a|<1,=1,>1$。

### ARCH-STATE-C03
说明 Bernoulli IID 参数预测中 $(s_t,t)$ 为什么比完整顺序更接近充分统计量；写出 likelihood。

## D. 边界、反例与纠错

### ARCH-STATE-D01
构造一个使用未来 token 的“伪因果”模型，并给出能发现泄露的单元测试。

### ARCH-STATE-D02
反驳：“状态向量使用 float32，所以它能无损保存任意长文本。”

### ARCH-STATE-D03
给出只做 loss mask 仍让 padding 改变最终状态的例子。

## E. AI 迁移

### ARCH-STATE-E01
为流式语音模型写状态 API 合同，至少包括 initialize、step、reset、dtype/device 与 batch resize。

### ARCH-STATE-E02
设计 benchmark 分开测 training throughput、prefill throughput、single-step latency 和 state memory。

### ARCH-STATE-E03
比较固定状态递推与显式 token cache：列出信息、计算、内存和故障四个维度。

# 实验 - 稳定归约、点积消去与混合精度累加

> [!question] 本实验的判别问题
> 归约树、补偿算法和累加精度分别控制哪种误差，为什么仅报告输入 dtype 不能描述点积或 GEMM 的数值质量？

## 设计与复现契约

| 面板 | 输入 | 比较 |
|---|---|---|
| A | $1+n2^{-24}$ | 顺序 FP32、pairwise FP32、Kahan FP32 |
| B | $(a+1)-a$ | 坏顺序、先消大数、Neumaier |
| C | FP16 量化项的点积 | FP16、顺序 FP32、pairwise FP32 accumulator |

## 结果

先用图回答：**顺序、树归约、补偿与 FP16/FP32 accumulator 分别在什么构造上拉开误差数量级？**

![[00-知识库管理/_assets/plots/stable-kernels/plot-stable-reductions-matmul-v2.svg|880]]

> [!figure] 实验图｜storage、multiply 与 accumulate precision 必须分开报告
> A 比较 sequential、pairwise 与 Kahan FP32 求和；B 用同一三项点积展示浮点加法不结合；C 先把输入量化到 FP16，再比较 FP16、顺序 FP32 与 pairwise FP32 累加。生成脚本：[[plot_stable_reductions_matmul.py]]；标准库软件舍入、无随机数，并对三组分离现象设确定性断言。

**怎样读图。** A 读红线随 $n$ 的累积增长和两条稳定曲线的显示地板；B 找到红线从 0 跳到 1 的消去尺度；C 先固定“输入已量化”这一共同条件，再比较 accumulator 精度与归约树带来的纵向差异。

**适用边界（图没有证明什么）。** 数据是刻意构造的压力测试，未测吞吐、带宽、通信、次正规数、TF32 或真实 GPU 调度；pairwise/Kahan 的零误差不代表对任意输入精确，FP32 accumulator 的优势也不消除 FP16 输入量化误差。

| 代表点 | 结果 |
|---|---:|
| $n=65536$ 顺序求和相对误差 | $3.891\times10^{-3}$ |
| 同一构造中 pairwise/Kahan | 本实验打印精度下为 0 |
| $a=2^{24}$ 的 $(a+1)-a$ 绝对误差 | $1$ |
| 先算 $(a-a)+1$/Neumaier | $0$ |
| $k=4096$ FP16 accumulator 归一化误差 | $2.307\times10^{-4}$ |
| $k=4096$ 顺序/pairwise FP32 accumulator | $1.748\times10^{-8}$ / $7.705\times10^{-9}$ |

面板 A 是特意构造的半 ulp 吸收例，“误差为 0”只说明该构造被精确恢复，不表示 pairwise/Kahan 对所有输入精确。面板 C 分离了“输入已 FP16 量化”和“在何种精度累加”。

## 局限

- 软件舍入模型不包含特定 GPU 的次正规数、TF32 和调度语义；
- 点积数据是确定性压力测试，不代表真实模型分布；
- 本实验比较精度，未测吞吐、带宽和通信。
